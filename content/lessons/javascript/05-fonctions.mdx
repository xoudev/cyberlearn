Tu écris un calcul, il marche, et trois écrans plus loin tu en as encore besoin. Tu pourrais recopier les mêmes lignes. Mauvaise idée : le jour où tu corriges une erreur, tu dois la corriger à chaque endroit, et tu en oublies toujours un. La solution, c'est de donner un nom à ce bloc de code et de l'appeler quand tu veux. Ce bloc nommé, c'est une fonction.

JavaScript propose plusieurs façons d'écrire une fonction. On va voir la déclaration classique, l'expression de fonction, et la fonction fléchée. Elles se ressemblent beaucoup, et pourtant il y a une différence de fond entre elles qui surprend presque tout le monde au début. On y arrive à la fin.

## déclarer une fonction

La forme la plus directe utilise le mot-clé `function`, un nom, une liste de paramètres entre parenthèses, et un bloc entre accolades. À l'intérieur, `return` renvoie une valeur à celui qui a appelé la fonction.

<CodePlayground language="javascript" starterCode={`function direBonjour(prenom) {
  return "Bonjour " + prenom + " !";
}

const message = direBonjour("Lucie");
console.log(message); // Bonjour Lucie !
console.log(direBonjour("Karim")); // Bonjour Karim !`} />

Le paramètre `prenom` est une variable qui n'existe qu'à l'intérieur de la fonction. Au moment de l'appel, tu lui passes une valeur (on appelle ça un argument), et la fonction travaille avec.

Attention à `return`. Il ne sert pas à afficher. `console.log` affiche dans la console et ne rend rien au programme ; `return` renvoie une valeur que le reste du code peut récupérer. Une fonction qui n'a pas de `return` renvoie `undefined`.

<CodePlayground language="javascript" starterCode={`function double(n) {
  return n * 2;
}

const r = double(5);
console.log(r + 1); // 11 : on réutilise la valeur renvoyée

function afficheDouble(n) {
  console.log(n * 2); // affiche, mais ne renvoie rien
}

const vide = afficheDouble(5); // affiche 10
console.log(vide); // undefined`} />

Autre point : dès que `return` s'exécute, la fonction s'arrête. Les lignes qui suivent le `return` ne tournent jamais.

## la fonction fléchée

Il existe une écriture plus courte. On enlève `function`, on garde les paramètres entre parenthèses, et on met une flèche `=>` avant le corps. Voici la même fonction des deux manières.

<CodePlayground language="javascript" starterCode={`// avec function, stockée dans une variable (expression de fonction)
const triple = function (n) {
  return n * 3;
};

// version fléchée équivalente
const tripleFleche = (n) => {
  return n * 3;
};

console.log(triple(4)); // 12
console.log(tripleFleche(4)); // 12`} />

Quand le corps tient en une seule expression à renvoyer, tu peux retirer les accolades et le mot `return`. La valeur de l'expression est alors renvoyée toute seule. On appelle ça le return implicite.

<CodePlayground language="javascript" starterCode={`const carre = (n) => n * n;
const addition = (a, b) => a + b;

console.log(carre(6)); // 36
console.log(addition(3, 7)); // 10`} />

La fléchée brille là où on a besoin d'une petite fonction jetable, sur une seule ligne, surtout quand on la passe à une autre fonction. C'est le cas qu'on voit juste après. Pour une grosse fonction nommée avec plusieurs instructions, la forme `function` reste souvent plus lisible. Choisis selon le contexte, pas par réflexe.

## paramètres et valeurs par défaut

Une fonction peut prendre plusieurs paramètres, séparés par des virgules. Tu peux aussi donner une valeur par défaut à un paramètre : elle s'applique si l'appelant ne fournit rien pour cet argument.

<CodePlayground language="javascript" starterCode={`function saluer(prenom, salutation = "Bonjour") {
  return salutation + " " + prenom + " !";
}

console.log(saluer("Sofia")); // Bonjour Sofia !
console.log(saluer("Sofia", "Bonsoir")); // Bonsoir Sofia !

const prix = (montant, tva = 0.2) => montant * (1 + tva);
console.log(prix(100)); // 120
console.log(prix(100, 0.05)); // 105`} />

La valeur par défaut ne se déclenche que si l'argument est absent (ou vaut `undefined`). Si tu passes `0` ou une chaîne vide, ces valeurs sont prises telles quelles, parce que ce sont de vraies valeurs.

## les fonctions sont des valeurs

Voici l'idée qui ouvre tout le reste. En JavaScript, une fonction est une valeur, comme un nombre ou une chaîne. Tu peux la ranger dans une variable (on l'a déjà fait avec `triple`), mais surtout tu peux la passer en argument à une autre fonction.

<CodePlayground language="javascript" starterCode={`function appliquerDeux(fonction, valeur) {
  // on appelle la fonction reçue, deux fois
  return fonction(fonction(valeur));
}

const ajouterUn = (n) => n + 1;

console.log(appliquerDeux(ajouterUn, 5)); // 7
console.log(appliquerDeux((n) => n * 10, 3)); // 300`} />

Remarque que `ajouterUn` est passé sans parenthèses : on donne la fonction elle-même, pas son résultat. C'est `appliquerDeux` qui décide quand et combien de fois l'appeler.

Ce mécanisme est la base de méthodes que tu croiseras très vite sur les tableaux, comme `map` et `filter`. Tu leur donnes une petite fonction, et elles l'appliquent à chaque élément. Voici un avant-goût.

<CodePlayground language="javascript" starterCode={`const nombres = [1, 2, 3, 4];

// map applique la fonction à chaque élément
const doubles = nombres.map((n) => n * 2);
console.log(doubles); // [2, 4, 6, 8]

const pairs = nombres.filter((n) => n % 2 === 0);
console.log(pairs); // [2, 4]`} />

Tu vois pourquoi la fléchée courte est si pratique ici : la fonction passée tient sur une ligne.

## un mot sur this

Il reste une différence entre `function` et la fléchée, et ce n'est pas qu'une histoire de longueur. Beaucoup pensent que la fléchée est juste un `function` plus court. C'est faux, et ça crée des bugs.

Le point concerne `this`. Tu n'as pas encore besoin de maîtriser `this` à fond ; retiens seulement la règle. Une fonction écrite avec `function` crée son propre `this`, qui dépend de la façon dont elle est appelée. Une fonction fléchée, elle, ne crée pas son propre `this` : elle garde celui du code autour d'elle.

En pratique, ça veut dire que les deux écritures ne sont pas toujours interchangeables. À l'intérieur d'un objet ou d'une classe, remplacer une `function` par une fléchée (ou l'inverse) peut changer ce que vaut `this`, et donc casser le code sans message d'erreur évident. Quand tu apprendras les objets et les classes, garde ce piège en tête : ce n'est pas un détail de style, c'est un comportement différent.

## à retenir

- Une fonction nomme un bloc de code pour le réutiliser ; `function nom(params) { ... }` avec `return` pour renvoyer une valeur.
- `return` renvoie une valeur exploitable et arrête la fonction ; `console.log` se contente d'afficher. Sans `return`, le résultat est `undefined`.
- Une valeur par défaut s'écrit `param = valeur` et ne s'applique que si l'argument est absent.
- La fonction fléchée `=>` est une écriture courte ; en une seule expression, le `return` est implicite.
- Une fonction est une valeur : on peut la ranger dans une variable et la passer en argument. C'est ce que font `map` et `filter`.
- La fléchée ne crée pas son propre `this`, contrairement à `function`. Ce n'est pas qu'une question de syntaxe, et ça compte dès qu'on touche aux objets et aux classes.
