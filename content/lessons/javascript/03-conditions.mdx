Un programme qui suit toujours la même ligne droite n'est pas très utile. Tout l'intérêt arrive quand le code regarde une donnée et décide quoi faire en fonction. Est-ce que cet utilisateur a le droit d'entrer ? Le panier dépasse-t-il 50 euros ? Le mot de passe est-il correct ? À chaque fois, le programme pose une question et bifurque selon la réponse. Les conditions sont l'outil qui rend ça possible. Sans elles, ton code ferait exactement la même chose à chaque exécution, peu importe les données.

## if, else if, else

La forme de base, c'est `if`. Tu mets une condition entre parenthèses ; si elle est vraie, le bloc entre accolades s'exécute. Sinon, il est ignoré. Tu peux ajouter `else if` pour tester d'autres cas, et `else` pour ramasser tout ce qui n'a rien déclenché.

<CodePlayground language="javascript">

```javascript
const note = 14;

if (note >= 16) {
  console.log('Très bien');
} else if (note >= 12) {
  console.log('Bien');
} else if (note >= 10) {
  console.log('Passable');
} else {
  console.log('Insuffisant');
}
```

</CodePlayground>

JavaScript lit les conditions de haut en bas et s'arrête à la première qui est vraie. Ici `note >= 16` est fausse, mais `note >= 12` est vraie, donc il affiche Bien et ne regarde même pas les conditions suivantes. C'est pour ça que l'ordre compte : si tu mets `note >= 10` en premier, une note de 18 tomberait dans Passable et n'arriverait jamais jusqu'à Très bien. Range tes conditions de la plus stricte à la plus large.

Le `else` n'est pas obligatoire. Un `if` tout seul est parfaitement valide quand tu veux juste agir dans un cas précis et ne rien faire le reste du temps.

## truthy et falsy

Voilà un point qui surprend souvent au début. La condition d'un `if` n'a pas besoin d'être un vrai booléen `true` ou `false`. Tu peux mettre n'importe quelle valeur, et JavaScript la convertit en booléen au moment de tester. C'est plus large qu'on ne le croit : ce n'est pas réservé à `true` et `false`, chaque valeur du langage a une « teinte » de vrai ou de faux.

Les valeurs qui comptent comme fausses s'appellent les valeurs falsy. Il y en a exactement six : `false`, `0`, la chaîne vide `''`, `null`, `undefined`, et `NaN`. Tout le reste est truthy.

<CodePlayground language="javascript">

```javascript
const prenom = '';

if (prenom) {
  console.log('Bonjour ' + prenom);
} else {
  console.log('Aucun prénom fourni');
}

// La chaîne vide est falsy, donc on tombe dans le else.
// Test rapide d'autres valeurs :
console.log(Boolean(0));        // false
console.log(Boolean('0'));      // true  -> une chaîne non vide est truthy
console.log(Boolean([]));       // true  -> un tableau vide reste truthy
console.log(Boolean(undefined)); // false
```

</CodePlayground>

C'est pratique parce que ça raccourcit le code. Plutôt que d'écrire `if (prenom !== '' && prenom !== undefined)`, tu écris juste `if (prenom)`. Mais c'est aussi un piège classique. Le plus courant : tester un nombre. Si tu écris `if (quantite)` pour vérifier qu'une quantité existe, le cas `quantite === 0` passera dans le `else` alors que zéro est peut-être une valeur tout à fait légitime. Pareil avec la chaîne vide qui est parfois une saisie valable. Quand tu veux vraiment savoir si une variable est définie, sois explicite : `if (quantite !== undefined)` dit exactement ce que tu veux, sans surprise.

Cette conversion automatique alimente aussi une astuce qu'on appelle le court-circuit. L'opérateur `||` renvoie sa première valeur truthy, ce qui permet de poser une valeur par défaut.

<CodePlayground language="javascript">

```javascript
function saluer(nom) {
  const affichage = nom || 'invité';
  return 'Bonjour ' + affichage;
}

console.log(saluer('Léa'));  // Bonjour Léa
console.log(saluer(''));     // Bonjour invité  (chaîne vide = falsy)
console.log(saluer());       // Bonjour invité  (undefined = falsy)
```

</CodePlayground>

Attention au même piège ici : `0 || 10` donne `10`, parce que `0` est falsy. Si zéro est une valeur que tu veux garder, l'opérateur `??` (nullish) est plus sûr, car il ne se déclenche que pour `null` et `undefined`.

## switch

Quand tu compares une seule et même variable à toute une liste de valeurs précises, enchaîner les `else if` devient pénible à lire. Le `switch` est fait pour ça. Il évalue une valeur, puis cherche le `case` qui correspond avec une égalité stricte. Le `default` joue le rôle du `else`.

<CodePlayground language="javascript">

```javascript
const jour = 'mardi';

switch (jour) {
  case 'samedi':
  case 'dimanche':
    console.log("C'est le week-end");
    break;
  case 'mardi':
    console.log('Bon courage, on est mardi');
    break;
  default:
    console.log('Jour de semaine ordinaire');
}
```

</CodePlayground>

Tu remarques que `samedi` et `dimanche` partagent le même bloc. C'est volontaire : un `case` sans corps enchaîne sur le suivant, ce qui sert à regrouper plusieurs valeurs sur un même traitement. Mais cette mécanique a un revers, et c'est le vrai piège du `switch`.

<Callout type="warning">
Si tu oublies un `break`, l'exécution ne s'arrête pas à la fin du case trouvé : elle déborde et continue dans le case suivant, puis le suivant, jusqu'à rencontrer un `break` ou la fin du switch. On appelle ça le fall-through. Le code fait alors plus que ce que tu crois, et le bug est sournois parce que tout a l'air correct à la lecture.
</Callout>

<CodePlayground language="javascript">

```javascript
const role = 'editeur';

switch (role) {
  case 'admin':
    console.log('Peut supprimer');
  // break oublié ici : on déborde sur le case suivant
  case 'editeur':
    console.log('Peut modifier');
    break;
  case 'lecteur':
    console.log('Peut lire');
    break;
}

// Avec 'admin', tu verrais 'Peut supprimer' PUIS 'Peut modifier',
// parce que le premier case n'a pas de break. Teste en mettant role = 'admin'.
```

</CodePlayground>

La règle pratique : mets un `break` à la fin de chaque `case`, et ne supprime ce `break` que quand tu veux délibérément regrouper des cas. Le dernier `case` ou le `default` peut s'en passer puisqu'il n'y a rien après, mais beaucoup le laissent quand même par habitude.

## le ternaire

Il arrive souvent qu'un `if/else` ne serve qu'à choisir entre deux valeurs pour les ranger dans une variable. Dans ce cas précis, l'opérateur ternaire fait la même chose en une ligne. Sa forme est `condition ? valeurSiVrai : valeurSiFaux`. Le point d'interrogation sépare la condition du premier choix, les deux-points séparent les deux choix.

<CodePlayground language="javascript">

```javascript
const age = 20;
const statut = age >= 18 ? 'majeur' : 'mineur';
console.log(statut); // majeur

const heure = 9;
const message = heure < 12 ? 'Bonjour' : 'Bonsoir';
console.log(message); // Bonjour
```

</CodePlayground>

L'avantage du ternaire, c'est qu'il produit une valeur, donc tu peux l'affecter directement. Un `if/else` classique, lui, ne renvoie rien : il faudrait déclarer la variable au-dessus puis l'assigner dans chaque branche. Le ternaire condense tout ça.

Mais garde-le pour les choix courts. Dès que tu commences à imbriquer des ternaires les uns dans les autres, ou que la condition s'allonge, la ligne devient illisible et un `if/else` redevient le bon choix. Le ternaire gagne sur les cas simples, pas sur la logique compliquée.

## à retenir

- `if`, `else if` et `else` testent les conditions de haut en bas et s'arrêtent à la première vraie ; range-les de la plus stricte à la plus large.
- Une condition convertit sa valeur en booléen. Les six valeurs falsy sont `false`, `0`, `''`, `null`, `undefined` et `NaN`. Tout le reste, y compris `'0'`, `[]` et `{}`, est truthy.
- Tester directement un nombre ou une chaîne avec `if (x)` peut piéger sur `0` ou `''` ; quand tu veux savoir si une variable existe, écris `if (x !== undefined)`.
- Le court-circuit `||` donne une valeur par défaut, mais traite `0` et `''` comme absents ; utilise `??` quand tu veux conserver ces valeurs.
- Le `switch` compare une valeur à plusieurs `case` en égalité stricte ; un `break` oublié provoque le fall-through et l'exécution déborde sur les cas suivants.
- Le ternaire `condition ? a : b` renvoie une valeur et remplace un `if/else` simple ; évite-le dès que la logique s'imbrique.
