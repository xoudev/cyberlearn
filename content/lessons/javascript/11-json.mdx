Quand un navigateur demande des données à un serveur, les deux machines ne partagent pas de mémoire. Elles s'envoient simplement du texte sur le réseau. Pour que ce texte ait un sens des deux côtés, il faut un format commun, une façon convenue d'écrire des données structurées. Sur le web, ce format s'appelle JSON. Vous le retrouvez aussi dès qu'il faut sauvegarder des préférences ou écrire un fichier de configuration. C'est le sujet de cette leçon.

## objet JS contre chaîne JSON

JSON veut dire JavaScript Object Notation. Le nom prête à confusion, alors mettons les choses au clair tout de suite : JSON n'est pas du JavaScript. C'est un format de texte. Sa syntaxe a été inspirée par la façon d'écrire les objets en JavaScript, mais aujourd'hui Python, Java, Go, PHP et à peu près tous les langages savent lire et produire du JSON. Il est indépendant du langage.

La distinction qui compte le plus est celle entre un objet et une chaîne. Un objet JavaScript vit en mémoire pendant que votre programme tourne. Vous accédez à ses propriétés, vous appelez des méthodes dessus, vous le modifiez. Une chaîne JSON, elle, est juste une suite de caractères. Elle représente les mêmes données, mais sous une forme inerte, transportable et stockable.

<CodePlayground language="javascript" starterCode={`const user = { name: 'Amélie', level: 7 };
const text = '{ "name": "Amélie", "level": 7 }';

// L'objet : on accède à ses propriétés
console.log(user.level + 1);

// La chaîne : c'est du texte, on en mesure la longueur
console.log(text.length);
console.log(typeof user);
console.log(typeof text);`} />

L'objet répond à `user.level`. La chaîne, elle, ne connaît que des opérations de texte comme `.length`. Si vous tentez `text.level`, vous obtenez `undefined`, parce qu'une chaîne n'a pas de propriété `level`. Garder cette frontière en tête évite la moitié des bugs liés à JSON.

## stringify et parse

Pour passer d'un côté à l'autre de cette frontière, JavaScript fournit deux fonctions. `JSON.stringify` prend un objet en mémoire et le transforme en chaîne de texte, prête à être envoyée sur le réseau ou écrite dans un fichier. `JSON.parse` fait l'inverse : il prend une chaîne reçue et la reconstruit en objet exploitable.

<CodePlayground language="javascript" starterCode={`const product = { title: 'Clavier', price: 49.9, tags: ['azerty', 'usb'] };

// Objet vers texte
const text = JSON.stringify(product);
console.log(text);
console.log(typeof text);

// Texte vers objet
const back = JSON.parse(text);
console.log(back.price);
console.log(typeof back);`} />

Le troisième argument de `JSON.stringify` mérite un mot. Si vous lui passez un nombre, il indente la sortie avec ce nombre d'espaces, ce qui rend le texte lisible pour un humain. Le deuxième argument sert à filtrer les champs et vaut le plus souvent `null`.

<CodePlayground language="javascript" starterCode={`const config = { theme: 'sombre', sons: false, niveau: 3 };

const compact = JSON.stringify(config);
const lisible = JSON.stringify(config, null, 2);

console.log(compact);
console.log(lisible);`} />

La version compacte sert à transporter les données, la version indentée sert à les lire pendant le débogage.

## les règles de JSON

JSON ressemble à un objet JavaScript, mais ses règles sont plus strictes, et c'est volontaire. Toutes les clés sont entre guillemets doubles, jamais simples, jamais nues. Les chaînes de caractères aussi sont entre guillemets doubles. Pas de virgule après le dernier élément. Pas de fonctions ni de méthodes, puisque JSON ne transporte que des données. Pas de commentaires non plus, ce qui surprend souvent quand on édite un fichier de configuration à la main.

JSON ne connaît que six types de valeurs : une chaîne, un nombre, un booléen, la valeur `null`, un tableau et un objet. Une date, une fonction, une variable `undefined` n'ont pas de place directe dedans.

<CodePlayground language="javascript" starterCode={`// Valide en JSON
const ok = '{ "name": "Léa", "active": true, "tags": ["js"] }';
console.log(JSON.parse(ok).name);

// Invalide : guillemets simples et clé sans guillemets
const ko = "{ name: 'Léa' }";
try {
  JSON.parse(ko);
} catch (e) {
  console.log('Erreur de parsing : JSON invalide');
}`} />

Pourquoi tant de sévérité ? Parce qu'un langage commun ne fonctionne que si tout le monde respecte exactement la même grammaire. Si JavaScript autorisait les commentaires et les virgules finales mais pas Python, le texte ne serait plus universel. Les restrictions de JSON sont le prix de son interopérabilité. C'est aussi pour cela que `JSON.parse` est intransigeant : il lève une erreur dès qu'un caractère ne respecte pas la grammaire, plutôt que de deviner ce que vous vouliez dire.

## où on le rencontre

Trois endroits reviennent sans cesse. Les réponses d'API : quand votre code interroge un service distant, la réponse arrive en JSON, et vous la passez à `JSON.parse`. Les fichiers de configuration : le `package.json` d'un projet Node, par exemple, est un document JSON. Et le stockage du navigateur : `localStorage` ne sait conserver que des chaînes, donc on y range un objet en le stringifiant, et on le relit en le parsant.

Voici le cycle complet d'un usage de stockage. On part d'un objet, on le sérialise pour le ranger, puis on le relit plus tard.

<CodePlayground language="javascript" starterCode={`// On simule un stockage qui ne garde que du texte
let storage = '';

const settings = { langue: 'fr', notifications: true };

// Sauvegarde : objet vers texte
storage = JSON.stringify(settings);
console.log('Stocké :', storage);

// Relecture : texte vers objet
const loaded = JSON.parse(storage);
loaded.notifications = false;
console.log('Notifications :', loaded.notifications);`} />

Le piège classique guette ici. Si vous oubliez `JSON.parse` et que vous traitez le texte relu comme un objet, `loaded.notifications` vaut `undefined`, parce que vous interrogez une chaîne. Le piège symétrique existe aussi : envoyer un objet brut là où un texte est attendu, sans `JSON.stringify`. À chaque passage de frontière, demandez-vous si vous tenez un objet ou du texte, et appliquez la bonne fonction.

## à retenir

- JSON est un format de texte servant à échanger et stocker des données, lu et produit par presque tous les langages.
- Un objet JavaScript vit en mémoire et répond à `.propriete` ; une chaîne JSON est du texte inerte qui le représente.
- `JSON.stringify` transforme un objet en chaîne ; son troisième argument numérique contrôle l'indentation.
- `JSON.parse` transforme une chaîne en objet, et lève une erreur si le texte n'est pas un JSON valide.
- Les clés et les chaînes sont entre guillemets doubles ; pas de fonctions, pas de commentaires, pas de virgule finale.
- Le piège récurrent est de confondre objet et texte : à chaque frontière, applique parse ou stringify selon le sens.
