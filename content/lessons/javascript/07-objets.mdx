Une variable ne retient qu'une chose à la fois : un nombre, un texte, un booléen. Mais les données du monde réel arrivent rarement seules. Un utilisateur, c'est un nom, un âge, un courriel, un rôle. Une commande, c'est un produit, une quantité, un prix, une adresse. Garder tout ça dans des variables séparées (nomUtilisateur, ageUtilisateur, courrielUtilisateur) devient vite ingérable : rien ne dit que ces trois variables parlent de la même personne, et on les trimballe une par une dans chaque fonction.

L'objet règle ce problème. Il rassemble des données qui vont ensemble dans une seule structure, où chaque valeur porte un nom parlant. Au lieu de trois variables flottantes, on a un utilisateur avec un nom, un âge et un courriel rangés dedans. On passe l'objet entier d'une fonction à l'autre, et le lien entre les valeurs ne se perd jamais.

## créer et accéder

Un objet est une suite de paires clé-valeur. La clé, c'est le nom de la propriété ; la valeur, c'est ce qu'elle contient. On lit une propriété de deux façons. La notation par point est la plus courante et la plus lisible. La notation par crochets sert quand le nom de la propriété vit dans une variable, ou contient un caractère que le point n'accepte pas (un espace, un tiret).

Ajouter ou modifier une propriété se fait avec une simple affectation. Si la clé existe déjà, sa valeur est remplacée ; sinon, la propriété naît à ce moment-là. Le mot-clé delete retire une propriété.

<CodePlayground language="javascript" starterCode={`const utilisateur = {
  nom: 'Alice',
  age: 30,
  courriel: 'alice@exemple.fr',
};

// Accès par point
console.log(utilisateur.nom); // Alice

// Accès par crochets, utile quand la clé est dans une variable
const champ = 'age';
console.log(utilisateur[champ]); // 30

// Modifier une propriété existante
utilisateur.age = 31;

// Ajouter une nouvelle propriété au passage
utilisateur.actif = true;

// Retirer une propriété
delete utilisateur.courriel;

console.log(utilisateur);
// { nom: 'Alice', age: 31, actif: true }`} />

La notation par point devrait être votre réflexe. Gardez les crochets pour les cas où le nom de propriété n'est connu qu'à l'exécution, par exemple une clé lue depuis un formulaire ou une boucle.

## les méthodes

Une valeur dans un objet peut très bien être une fonction. On parle alors de méthode : un comportement rangé à côté des données qu'il manipule. Dans une méthode, le mot-clé this renvoie à l'objet sur lequel on a appelé la méthode. C'est ce qui permet à la fonction de lire les autres propriétés du même objet sans qu'on lui passe quoi que ce soit.

La règle à retenir pour l'instant est simple : quand vous écrivez objet.methode(), à l'intérieur de cette méthode this désigne objet, c'est-à-dire ce qui se trouve à gauche du point.

<CodePlayground language="javascript" starterCode={`const compte = {
  titulaire: 'Karim',
  solde: 100,

  deposer(montant) {
    this.solde = this.solde + montant;
    return this.solde;
  },

  resume() {
    return this.titulaire + ' a ' + this.solde + ' euros.';
  },
};

console.log(compte.resume());   // Karim a 100 euros.
compte.deposer(50);
console.log(compte.resume());   // Karim a 150 euros.`} />

Remarquez que deposer modifie this.solde, et que resume relit cette même valeur. Les deux méthodes travaillent sur le même objet parce que this pointe vers lui à chaque appel.

## la destructuration

Lire les propriétés une par une devient répétitif dès qu'il y en a plusieurs. La destructuration extrait des propriétés dans des variables en une seule ligne. On écrit, à gauche du signe égal, les noms des propriétés voulues entre accolades. Chaque variable récupère la valeur de la propriété du même nom. On peut renommer une variable au passage, et fournir une valeur par défaut quand la propriété est absente.

Là où la destructuration devient vraiment agréable, c'est dans les paramètres d'une fonction. Plutôt que de recevoir un objet entier et d'écrire commande.client, commande.total partout, on extrait directement les champs utiles dans la signature.

<CodePlayground language="javascript" starterCode={`const config = {
  hote: 'localhost',
  port: 5432,
};

// Extraire deux propriétés d'un coup
const { hote, port } = config;
console.log(hote, port); // localhost 5432

// Renommer (ssl -> securise) et donner un défaut (delai)
const { ssl: securise = false, delai = 30 } = config;
console.log(securise); // false (valeur par défaut, ssl absent)
console.log(delai);    // 30

// Destructuration directement dans un paramètre
function afficher({ nom, role = 'invite' }) {
  return nom + ' (' + role + ')';
}

console.log(afficher({ nom: 'Lea' }));            // Lea (invite)
console.log(afficher({ nom: 'Sam', role: 'admin' })); // Sam (admin)`} />

## le spread et le rest

Les trois points (...) ont deux usages opposés selon le contexte. En spread, ils étalent les propriétés d'un objet existant à l'intérieur d'un autre. C'est la façon la plus courante de copier un objet en changeant quelques champs, ou de fusionner deux objets. Les propriétés écrites après celles qui sont étalées l'emportent en cas de conflit de clé.

En rest, les trois points font l'inverse : ils rassemblent ce qui reste. Dans une destructuration, le rest collecte toutes les propriétés non nommées dans un nouvel objet.

<CodePlayground language="javascript" starterCode={`const base = { nom: 'Alice', age: 30, ville: 'Lyon' };

// Spread : copier puis remplacer un champ
const misAJour = { ...base, age: 31 };
console.log(misAJour); // { nom: 'Alice', age: 31, ville: 'Lyon' }

// Spread : fusionner deux objets (le dernier gagne en cas de conflit)
const defauts = { theme: 'clair', langue: 'fr' };
const choix   = { theme: 'sombre' };
const reglages = { ...defauts, ...choix };
console.log(reglages); // { theme: 'sombre', langue: 'fr' }

// Rest : isoler une propriété, regrouper le reste
const { nom, ...autres } = base;
console.log(nom);    // Alice
console.log(autres); // { age: 30, ville: 'Lyon' }`} />

## passés par référence

Voici le point qui surprend tout le monde au moins une fois. Quand on affecte un objet à une nouvelle variable avec le signe égal, on ne crée pas une copie. Les deux variables désignent le même objet en mémoire. Modifier une propriété via l'une se voit immédiatement via l'autre, parce qu'il n'y a qu'un seul objet, partagé.

C'est différent des valeurs simples comme les nombres ou les chaînes. Avec un nombre, copier la variable copie la valeur, et les deux mènent leur vie séparément. Avec un objet, copier la variable copie seulement la référence, l'adresse de l'objet, pas son contenu.

<Callout type="warning">
Le piège classique : on écrit const copie = original en croyant travailler sur un double, on modifie copie, et original change aussi. Les deux noms pointaient vers le même objet depuis le début. Pour obtenir une vraie copie indépendante, il faut la demander explicitement.
</Callout>

Pour copier réellement, deux outils. Le spread (...) crée un nouvel objet avec les mêmes propriétés de premier niveau ; c'est suffisant pour un objet plat. Pour un objet imbriqué (un objet qui contient d'autres objets), structuredClone fait une copie complète en profondeur.

<CodePlayground language="javascript" starterCode={`const original = { nom: 'Alice', age: 30 };

// FAUX : pas une copie, juste un second nom pour le même objet
const alias = original;
alias.age = 99;
console.log(original.age); // 99  <- l'original a bougé !

// VRAI : le spread crée un nouvel objet plat
const copie = { ...original };
copie.age = 18;
console.log(original.age); // 99  <- l'original ne bouge plus
console.log(copie.age);    // 18

// Pour un objet imbriqué, structuredClone copie en profondeur
const compte = { titulaire: 'Sam', adresse: { ville: 'Lyon' } };
const vraieCopie = structuredClone(compte);
vraieCopie.adresse.ville = 'Paris';
console.log(compte.adresse.ville); // Lyon  <- intact`} />

Notez bien la limite du spread sur le dernier exemple : un spread de compte copierait l'objet du dessus, mais adresse resterait partagé entre les deux. C'est pour ça que structuredClone existe quand il y a des niveaux imbriqués.

## à retenir

- Un objet range des données liées en paires clé-valeur ; on lit par point (obj.cle) ou par crochets (obj[cle]) quand la clé est dynamique.
- Les objets sont mutables : on ajoute, modifie ou supprime (delete) une propriété quand on veut.
- Une méthode est une fonction stockée dans un objet ; this y désigne l'objet à gauche du point lors de l'appel.
- La destructuration extrait des propriétés en variables d'un coup, avec renommage et valeurs par défaut, très pratique dans les paramètres.
- Le spread (...) copie ou fusionne des objets de premier niveau ; le rest rassemble les propriétés restantes.
- Affecter un objet avec le signe égal partage la référence, pas le contenu : modifier l'un modifie l'autre. Pour vraiment copier, utilisez le spread (objet plat) ou structuredClone (objet imbriqué).
