Jusqu'ici, nos programmes exécutaient leurs lignes l'une après l'autre, toujours dans le même ordre, quelles que soient les données. Un vrai programme doit **décider** : autoriser ou refuser une connexion, afficher un message d'erreur ou le résultat, signaler une adresse suspecte ou la laisser passer. Toutes ces décisions reposent sur un petit nombre d'outils : des **comparaisons** qui donnent vrai ou faux, des **conditions** qui choisissent quel bloc exécuter, et trois opérateurs logiques, **et**, **ou**, **non**, pour combiner les critères. Cette logique, dite booléenne en hommage au mathématicien George Boole, est aussi celle des circuits du processeur : les transistors du module 2, assemblés en portes ET, OU et NON, calculent exactement ces opérations. Elle est simple, mais une seule erreur dans une condition peut ouvrir une porte qui devait rester fermée.

## objectifs

À la fin de cette leçon, tu sais :

- écrire une comparaison et prévoir son résultat ;
- faire choisir un programme avec `if`, `elif` et `else` ;
- combiner des critères avec `and`, `or` et `not` ;
- dresser la table de vérité d'une expression ;
- appliquer les lois de De Morgan pour simplifier ou inverser une condition ;
- repérer les erreurs de logique les plus courantes, dont celles qui créent des failles.

## pourquoi ça compte

Le **contrôle d'accès** d'une application, c'est-à-dire la partie qui décide qui a le droit de faire quoi, n'est rien d'autre qu'un ensemble de conditions. Et le contrôle d'accès défaillant est, depuis 2021, la catégorie de failles numéro un du classement de l'OWASP, la référence mondiale en sécurité des applications web. Derrière beaucoup de ces failles, il y a une condition mal écrite : un `ou` à la place d'un `et`, un cas oublié, une vérification faite dans le mauvais ordre. Savoir lire et écrire une condition sans ambiguïté, c'est à la fois une compétence de développeur et une compétence d'auditeur.

## les comparaisons

Une **comparaison** confronte deux valeurs et donne un booléen, `True` ou `False`. Python en a six :

| Opérateur | Signification | Exemple | Résultat |
|---|---|---|---|
| `==` | égal à | `3 == 3` | `True` |
| `!=` | différent de | `"alice" != "Alice"` | `True` |
| `<` | strictement inférieur | `2 < 2` | `False` |
| `<=` | inférieur ou égal | `2 <= 2` | `True` |
| `>` | strictement supérieur | `10 > 9` | `True` |
| `>=` | supérieur ou égal | `17 >= 18` | `False` |

Le test d'égalité s'écrit avec **deux** signes égal. Un seul, tu le sais, est une affectation. Python refuse d'ailleurs `if age = 18:` avec une `SyntaxError`, ce qui évite un bug célèbre du langage C, où cette ligne est acceptée et affecte 18 à `age` au lieu de le comparer.

Les textes se comparent **exactement** : `"alice" == "Alice"` est faux, et `"alice " == "alice"` aussi, à cause de l'espace final. Quand on compare une saisie utilisateur, on la nettoie souvent d'abord avec `.strip()`, qui enlève les espaces autour, et `.lower()`, qui met tout en minuscules.

Python permet d'**enchaîner** les comparaisons comme en mathématiques : `0 <= note <= 20` vérifie que la note est entre 0 et 20 inclus. La plupart des autres langages imposent d'écrire les deux moitiés séparément.

## if, elif, else

L'instruction `if` exécute un bloc seulement si une condition est vraie :

```python
tentatives = 5
if tentatives >= 3:
    print("Compte verrouillé")
print("Fin de la vérification")
```

Trois détails de syntaxe comptent. La ligne du `if` se termine par un **deux-points**. Le bloc qui en dépend est **indenté**, par convention de quatre espaces. Et c'est l'indentation, et elle seule, qui marque la fin du bloc : la dernière ligne, revenue à gauche, s'exécute dans tous les cas. En Python, l'indentation n'est pas une question de présentation, elle fait partie du sens.

`else` donne le bloc à exécuter sinon, et `elif` (contraction de *else if*) enchaîne d'autres conditions :

```python
if note >= 16:
    mention = "très bien"
elif note >= 14:
    mention = "bien"
elif note >= 12:
    mention = "assez bien"
elif note >= 10:
    mention = "passable"
else:
    mention = "ajourné"
```

Python teste les conditions **dans l'ordre** et exécute **uniquement** le premier bloc dont la condition est vraie ; les autres sont ignorés. Pour une note de 17, la première condition suffit, même si `note >= 14` est vraie aussi. C'est pourquoi l'ordre compte : si l'on testait `note >= 10` en premier, tout le monde aurait « passable ».

## et, ou, non

Une décision dépend souvent de plusieurs critères. Trois opérateurs les combinent.

**`and`** (et) est vrai seulement si **les deux** côtés sont vrais. « Le compte est actif et le mot de passe est correct. »

**`or`** (ou) est vrai si **au moins un** des côtés est vrai. « L'utilisateur est administrateur ou propriétaire du document. » C'est un ou **inclusif** : si les deux sont vrais, le résultat est vrai aussi.

**`not`** (non) inverse une valeur : `not True` vaut `False`.

On résume leur comportement dans des **tables de vérité**, qui listent toutes les combinaisons possibles :

| A | B | A and B | A or B | not A |
|---|---|---|---|---|
| False | False | False | False | True |
| False | True | False | True | True |
| True | False | False | True | False |
| True | True | True | True | False |

Avec deux variables, il y a quatre lignes ; avec trois, huit ; avec n variables, 2 puissance n. Dresser la table de vérité d'une condition compliquée est le moyen le plus sûr de vérifier qu'elle fait ce qu'on croit, et c'est exactement ce que font les concepteurs de circuits.

Comme en arithmétique, il y a des **priorités** : `not` s'applique en premier, puis `and`, puis `or`. Ainsi `a or b and c` se lit `a or (b and c)`. Plutôt que de retenir ces règles, mets des **parenthèses** dès qu'une condition mélange `and` et `or` : c'est plus sûr, et le lecteur n'a pas à réfléchir.

## les lois de De Morgan

Il arrive souvent qu'on doive **inverser** une condition : on a écrit quand accepter, on veut écrire quand refuser. Les lois de De Morgan donnent la règle :

- `not (A and B)` équivaut à `(not A) or (not B)` ;
- `not (A or B)` équivaut à `(not A) and (not B)`.

En français : « il est faux que les deux soient vrais » équivaut à « au moins un est faux ». Quand on fait entrer le `not` dans la parenthèse, le `and` devient `or` et réciproquement.

Exemple concret. On accepte une connexion si le compte est actif **et** le mot de passe correct. Quand la refuser ? Quand `not (actif and mdp_ok)`, c'est-à-dire quand le compte est **inactif ou** le mot de passe **faux**. Un seul des deux suffit. L'erreur classique consiste à écrire `not actif and not mdp_ok`, qui ne refuse que si les deux échouent : un compte désactivé avec le bon mot de passe passerait. Voilà une faille de contrôle d'accès en une ligne.

## l'évaluation paresseuse

Python évalue `and` et `or` de gauche à droite et **s'arrête dès que le résultat est connu**. Dans `A and B`, si `A` est faux, le résultat est faux quoi que vaille `B`, et `B` n'est même pas calculé. Dans `A or B`, si `A` est vrai, `B` est ignoré. On parle d'évaluation paresseuse, ou de **court-circuit**.

Ce n'est pas un détail : on s'en sert pour protéger une vérification. `utilisateur is not None and utilisateur.actif` ne consulte `actif` que si `utilisateur` existe ; dans l'autre ordre, le programme planterait sur un utilisateur absent. De même, `len(liste) > 0 and liste[0] == "admin"` n'accède au premier élément que si la liste n'est pas vide. L'ordre des critères d'un `and` n'est donc pas indifférent : on place d'abord ceux qui garantissent que les suivants ont un sens.

## les pièges de logique qui deviennent des failles

Le plus célèbre ressemble à ceci :

```python
if role == "admin" or "moderateur":
    print("Accès au panneau d'administration")
```

L'intention est claire : autoriser les administrateurs et les modérateurs. Mais Python lit `(role == "admin") or ("moderateur")`. Or un texte non vide est considéré comme vrai, tu l'as vu à la leçon précédente. La condition est donc **toujours vraie**, et n'importe qui accède au panneau. La bonne écriture répète la comparaison : `role == "admin" or role == "moderateur"`, ou plus élégamment `role in ("admin", "moderateur")`, qui teste l'appartenance à une liste de valeurs.

Deuxième piège : l'**autorisation par défaut**. Comparons deux façons d'écrire la même règle :

```python
# fragile : on refuse les cas connus, tout le reste passe
if role == "invite" or role == "banni":
    acces = False
else:
    acces = True

# robuste : on autorise les cas connus, tout le reste est refusé
if role == "admin" or role == "editeur":
    acces = True
else:
    acces = False
```

Le jour où quelqu'un crée un nouveau rôle, disons `"stagiaire"`, ou qu'un attaquant envoie un rôle inventé, la première version l'autorise et la seconde le refuse. C'est le principe du **refus par défaut** : en sécurité, le `else` doit être le cas le plus prudent.

Troisième piège : les **bornes**. `if age > 18` exclut les personnes de 18 ans ; `if age >= 18` les inclut. Le texte de la règle dit presque toujours lequel des deux on veut, et c'est l'un des premiers endroits où chercher un bug. On teste donc systématiquement les valeurs **juste avant**, **pile sur** et **juste après** chaque borne : 17, 18 et 19.

## les pièges

- **Écrire `=` au lieu de `==`.** Python le refuse dans un `if`, mais l'erreur de raisonnement reste fréquente dans d'autres langages.
- **Écrire `x == "a" or "b"`.** Le second morceau est un texte non vide, donc toujours vrai. Répète la comparaison, ou utilise `in`.
- **Mal ordonner les `elif`.** Seule la première condition vraie compte : du plus restrictif au plus large.
- **Se tromper de borne.** `>` ou `>=` : teste la valeur juste avant, pile sur et juste après.
- **Inverser une condition sans De Morgan.** `not (A and B)` n'est pas `not A and not B`.
- **Autoriser par défaut.** Le `else` d'un contrôle d'accès doit refuser.
- **Ignorer l'ordre d'un `and`.** Vérifie d'abord que la donnée existe, ensuite ce qu'elle contient.
- **Oublier les deux-points ou l'indentation.** C'est une `SyntaxError` ou une `IndentationError`, ou pire, une ligne qui sort du bloc sans prévenir.

## à retenir

- Une **comparaison** donne `True` ou `False`. L'égalité s'écrit `==`, la différence `!=`.
- `if` exécute un bloc si la condition est vraie ; `elif` et `else` enchaînent les cas. **Seule la première** condition vraie compte : l'ordre importe.
- Le **deux-points** et l'**indentation** délimitent les blocs.
- `and` : les deux ; `or` : au moins un ; `not` : l'inverse. Des **parenthèses** dès qu'on les mélange.
- **De Morgan** : `not (A and B)` = `not A or not B`, et inversement.
- **Court-circuit** : on vérifie d'abord que la donnée existe, ensuite ce qu'elle vaut.
- En sécurité : répéter les comparaisons (ou `in`), soigner les **bornes**, **refuser par défaut**.
