Tu utilises des fonctions depuis le début du module : `print`, `len`, `int`, `range`, `round`. Chacune cache quelques lignes, parfois des centaines, derrière un nom simple : tu écris `len(liste)` sans te demander comment Python compte les éléments. C'est tout l'intérêt d'une fonction : **nommer** un traitement pour s'en servir sans y repenser. Dans cette leçon, tu vas écrire les tiennes. C'est l'outil qui permet de passer de programmes de dix lignes à des programmes de dix mille, en appliquant la méthode de la première leçon du module : découper un gros problème en petits problèmes, et donner à chacun sa fonction.

## objectifs

À la fin de cette leçon, tu sais :

- définir une fonction avec `def` et l'appeler ;
- distinguer paramètres et arguments ;
- renvoyer un résultat avec `return`, et ne pas le confondre avec un affichage ;
- donner des valeurs par défaut aux paramètres ;
- expliquer la portée d'une variable : où elle existe, et où elle n'existe pas ;
- découper un problème en petites fonctions, et tester chacune séparément.

## pourquoi ça compte

Un programme sans fonctions est un long bloc où tout dépend de tout : pour corriger une ligne, il faut tout relire, et le même calcul copié-collé à cinq endroits doit être corrigé cinq fois, en espérant n'en oublier aucun. C'est d'ailleurs ainsi que naissent beaucoup de failles : une vérification d'entrée corrigée à un endroit, mais pas dans la copie d'à côté. Une fonction, c'est **un seul endroit** pour une règle. Si la validation des adresses IP ou le contrôle des droits est écrit une fois, dans une fonction appelée partout, une correction s'applique partout. Les bonnes pratiques de développement sécurisé le recommandent explicitement : centraliser les contrôles plutôt que les disperser.

## définir et appeler

Une fonction se **définit** avec le mot-clé `def`, son nom, ses **paramètres** entre parenthèses, et un deux-points. Son corps est indenté, comme celui d'un `if` ou d'une boucle :

```python
def aire_rectangle(largeur, hauteur):
    return largeur * hauteur
```

Définir une fonction ne l'exécute pas : cela crée seulement le nom `aire_rectangle`, prêt à servir. Pour l'exécuter, on l'**appelle** en lui passant des valeurs :

```python
a = aire_rectangle(4, 3)
print(a)                     # 12
print(aire_rectangle(2, 10)) # 20
```

À l'appel, Python associe chaque valeur à un paramètre, dans l'ordre : `largeur` reçoit 4, `hauteur` reçoit 3. Les valeurs passées s'appellent des **arguments** ; les noms qui les reçoivent, des **paramètres**. Puis le corps s'exécute, et `return` renvoie le résultat à l'endroit de l'appel, où il prend la place de l'appel : `aire_rectangle(4, 3)` « devient » 12.

On peut aussi nommer les arguments à l'appel, ce qui rend le code plus lisible et l'ordre indifférent : `aire_rectangle(hauteur=3, largeur=4)`.

Le schéma montre un point important : une fonction peut en appeler une autre. Le programme principal attend que `moyenne` lui réponde ; `moyenne` attend elle-même `somme`. Chaque appel est posé sur les précédents, comme une assiette sur une pile, puis retiré au retour. Cette **pile d'appels** est rangée en mémoire vive, et tu la reverras dans la prochaine leçon : c'est elle que Python affiche quand une erreur survient.

## renvoyer n'est pas afficher

C'est **la** confusion des débutants, et elle mérite une section entière. Compare ces deux fonctions :

```python
def double_affiche(n):
    print(n * 2)

def double_renvoie(n):
    return n * 2
```

Appelées seules, elles semblent identiques : `double_affiche(5)` montre 10 à l'écran, et dans l'éditeur, `print(double_renvoie(5))` aussi. Mais essaie de **réutiliser** le résultat :

```python
x = double_affiche(5) + 1    # affiche 10, puis TypeError
y = double_renvoie(5) + 1    # y vaut 11
```

`double_affiche` montre 10 à l'humain qui regarde l'écran, mais **ne rend rien** au programme. Une fonction sans `return` renvoie `None`, et `None + 1` est une erreur. `print` s'adresse à l'utilisateur ; `return` s'adresse au code qui a appelé la fonction. Une fonction de calcul doit **renvoyer** son résultat, et laisser l'appelant décider s'il veut l'afficher, l'enregistrer ou s'en servir pour un autre calcul. C'est aussi ce que vérifient les exercices : les tests comparent ce que ta fonction **renvoie**, pas ce qu'elle affiche.

Deux précisions sur `return`. Il **termine** immédiatement la fonction : les lignes qui suivent ne sont pas exécutées. On s'en sert pour sortir tôt quand un cas est réglé, comme dans le contrôle d'accès de la leçon sur les conditions. Et une fonction peut renvoyer plusieurs valeurs à la fois, sous forme de couple : `return plus_petit, position`, que tu as utilisé dans le premier exercice du module.

## les valeurs par défaut

Un paramètre peut avoir une **valeur par défaut**, utilisée quand l'appelant ne le précise pas :

```python
def verrouiller(tentatives, seuil=3):
    return tentatives >= seuil

verrouiller(4)            # True : le seuil vaut 3
verrouiller(4, seuil=5)   # False : seuil choisi par l'appelant
```

C'est très courant : `print` a ainsi un paramètre `sep`, le séparateur, qui vaut une espace par défaut, et `round` a un nombre de décimales qui vaut 0 si on ne le donne pas. Les paramètres avec valeur par défaut se placent après les autres.

## la portée des variables

Les paramètres et les variables créées **dans** une fonction sont **locaux** : ils n'existent que pendant l'exécution de la fonction, et disparaissent au retour.

```python
def taxer(prix):
    taux = 0.2
    return prix * (1 + taux)

print(taxer(100))   # 120.0
print(taux)         # NameError : taux n'existe pas ici
```

C'est une protection, pas une contrainte. Chaque fonction a son propre espace de noms : une variable `total` dans une fonction ne risque pas d'écraser la variable `total` d'une autre. On peut ainsi écrire et comprendre une fonction **sans connaître le reste** du programme. À l'inverse, une fonction peut **lire** une variable définie en dehors d'elle, une variable globale, mais c'est une mauvaise habitude : la fonction dépend alors d'un contexte invisible, et son résultat peut changer sans que ses arguments changent. La règle saine : **tout ce dont une fonction a besoin entre par ses paramètres, et tout ce qu'elle produit sort par `return`**. Une telle fonction est dite **pure**, et elle se teste en une ligne.

## découper un problème

Revenons au problème de la première leçon : signaler les utilisateurs qui ont échoué plus de trois fois. Découpé en fonctions, il devient :

```python
def est_echec(ligne):
    return ligne.startswith("ECHEC")

def utilisateur(ligne):
    # "ECHEC connexion utilisateur=bob ip=..." donne "bob"
    for morceau in ligne.split():
        if morceau.startswith("utilisateur="):
            return morceau[len("utilisateur="):]
    return None

def suspects(lignes, seuil=3):
    compte = {}
    for ligne in lignes:
        if est_echec(ligne):
            nom = utilisateur(ligne)
            compte[nom] = compte.get(nom, 0) + 1
    return [nom for nom, n in compte.items() if n > seuil]
```

Chaque fonction fait **une seule chose**, porte un nom qui dit laquelle, et tient en quelques lignes. La dernière utilise un **dictionnaire**, une structure qui associe des clés à des valeurs, ici chaque nom à son nombre d'échecs ; tu le découvriras en détail dans le parcours Python. Ce qui compte ici, c'est la forme : le programme principal se lit comme le pseudo-code, et chaque brique peut être testée isolément :

```python
assert est_echec("ECHEC connexion utilisateur=bob")
assert not est_echec("OK connexion utilisateur=bob")
assert utilisateur("ECHEC connexion utilisateur=bob ip=10.0.0.1") == "bob"
```

`assert` vérifie qu'une condition est vraie et arrête le programme sinon. C'est la forme la plus simple d'un **test automatique**, le même principe que les tests des exercices de la plateforme. Quand une fonction est courte et pure, on peut la tester sur tous ses cas limites en quelques lignes, et la réutiliser en confiance.

Comment savoir où couper ? Quelques signaux : un morceau de code qu'on a envie de copier-coller ; un commentaire qui annonce « maintenant, on calcule ceci », qui est en réalité le nom d'une fonction ; une boucle dans une boucle dans une condition ; une fonction qu'on ne peut plus lire d'un seul coup d'œil. Une bonne fonction tient souvent à l'écran, et se décrit en une phrase sans « et ».

## documenter

Une fonction réutilisée doit dire ce qu'elle attend et ce qu'elle renvoie. En Python, on place pour cela une **docstring**, une chaîne entre triples guillemets, juste sous la ligne `def` :

```python
def verrouiller(tentatives, seuil=3):
    """Renvoie True si le nombre de tentatives atteint le seuil de verrouillage."""
    return tentatives >= seuil
```

Les éditeurs de code l'affichent quand on survole un appel, et `help(verrouiller)` l'imprime. C'est le même mécanisme qui fournit l'aide intégrée de Python, comme `--help` pour les commandes du terminal au module 5.

## les fonctions des autres

Tu n'écris pas toutes les fonctions toi-même. Python est livré avec une **bibliothèque standard** de plusieurs centaines de modules, chacun rempli de fonctions testées par des milliers de développeurs : `math` pour les calculs, `random` pour le hasard, `hashlib` pour les empreintes que tu as vues au module 3, `ipaddress` pour manipuler les adresses réseau. On les rend disponibles avec `import`, puis on les appelle comme les tiennes : `import math` puis `math.sqrt(16)`.

Faut-il alors écrire soi-même ce qui existe déjà ? Pour apprendre, oui : c'est en écrivant un validateur d'adresses qu'on comprend ce qu'il doit vérifier. Dans un vrai projet, en revanche, une fonction éprouvée de la bibliothèque standard est presque toujours plus sûre que la tienne, surtout en sécurité, où les cas limites sont nombreux et subtils. Le réflexe professionnel : chercher d'abord si la fonction existe, lire sa documentation, puis l'utiliser.

## les pièges

- **Afficher au lieu de renvoyer.** Une fonction de calcul sans `return` renvoie `None`, et tout calcul fait ensuite avec son résultat échoue.
- **Oublier les parenthèses à l'appel.** `total = somme` attache la fonction elle-même au nom `total`, sans l'exécuter. Il faut `somme(valeurs)`.
- **Du code après `return`.** Il n'est jamais exécuté.
- **Compter sur une variable globale.** La fonction marche tant que le contexte ne change pas, puis casse sans raison apparente. Passe ce dont elle a besoin en paramètre.
- **Chercher une variable locale à l'extérieur.** Elle a disparu au retour de la fonction : `NameError`.
- **Des fonctions qui font tout.** Une fonction de quatre-vingts lignes qui lit, calcule, affiche et enregistre ne se teste pas. Une chose par fonction.
- **Des noms vagues.** `traiter`, `faire`, `fonction2` ne disent rien ; `est_echec`, `extraire_utilisateur` disent tout.

## à retenir

- `def nom(parametres):` **définit** une fonction ; `nom(arguments)` l'**appelle**.
- `return` **renvoie** une valeur au code appelant et termine la fonction. Sans `return`, c'est `None`. **Renvoyer n'est pas afficher.**
- Des **valeurs par défaut** rendent des paramètres facultatifs ; des **arguments nommés** rendent l'appel lisible.
- Les variables d'une fonction sont **locales**. Tout entre par les **paramètres**, tout sort par **`return`**.
- **Découper** : une fonction fait une chose, porte un nom qui la décrit, tient à l'écran, et se **teste** isolément avec `assert`.
- Une règle de sécurité écrite **une seule fois** se corrige une seule fois.
