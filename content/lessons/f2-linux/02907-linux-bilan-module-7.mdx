Le module 7 t'a fait passer de la commande tapée à la main au script qui tourne seul : le shebang et les arguments, les variables et les guillemets, les conditions, les boucles, les fonctions, la robustesse, les options, le débogage et la planification. Ce bilan vérifie les connaissances, puis te fait écrire **le** script que tout administrateur finit par écrire : une sauvegarde. Pas une sauvegarde de démonstration, une vraie, avec ses options, sa rotation, son journal et des codes de retour honnêtes, jugée par un banc de tests automatiques qui ne laisse rien passer.

## objectifs

Ce bilan valide que tu sais :

- écrire un script bash complet, structuré en fonctions ;
- accepter des options avec `getopts`, valider les entrées et respecter les codes de retour ;
- manipuler des noms de fichiers sans jamais les abîmer, espaces comprises ;
- rendre un script robuste : mode strict, fichiers temporaires nettoyés, échecs signalés ;
- garder une trace de chaque exécution dans un journal ;
- vérifier un script par des tests automatiques.

## projet

### la situation

Les données d'une petite équipe vivent dans un dossier, `donnees`. Il n'existe aucune sauvegarde. On te demande un script, `sauvegarde.sh`, qui sera planifié chaque nuit et que tes collègues lanceront aussi à la main. Il doit être fiable : si quelque chose échoue, il doit le dire, par son code de retour et dans son journal, et ne rien laisser traîner.

Le dossier de travail du terminal ci-dessous contient `donnees`, dont un fichier au nom piégeux, `compte rendu.txt`, et un banc de tests, **`tests.sh`**, qui vérifie onze comportements de ton script. Écris `sauvegarde.sh` dans ce même dossier, avec `vi`, ou dans ton éditeur habituel puis colle-le dans un here-document : `cat > sauvegarde.sh << 'FIN'`, le script, puis `FIN`.

### le cahier des charges

```text
Usage : sauvegarde.sh [-d DESTINATION] [-n NOMBRE] [-h] SOURCE
```

1. **L'archive.** Le script archive le dossier `SOURCE` dans `DESTINATION/NOM-AAAAMMJJ-HHMMSS.tar.gz`, où `NOM` est le nom du dossier source : `donnees-20261001-023000.tar.gz`. Le `tar` de ce petit Linux n'a pas `-z` : on passe par un tube vers `gzip`.
2. **Les options.** `-d` choisit la destination (par défaut `./sauvegardes`, créée si besoin), `-n` le nombre d'archives à garder (par défaut 5, un entier d'au moins 1), `-h` affiche l'aide.
3. **La rotation.** Après une sauvegarde réussie, seules les `NOMBRE` archives les plus récentes **de cette source** restent dans la destination. Les archives d'autres sources n'y sont jamais touchées.
4. **Le journal.** Chaque exécution ajoute au moins une ligne à `DESTINATION/sauvegarde.log`, avec la date, l'heure et `OK` ou `ERREUR` : `2026-10-01 02:30:00 OK donnees-20261001-023000.tar.gz créée`.
5. **Les codes de retour.** 0 en cas de succès ; 1 en cas d'échec, par exemple une source introuvable ou une destination impossible à créer, avec un message sur la sortie d'erreur et une ligne `ERREUR` au journal quand la destination existe ; 2 en cas de mauvaise utilisation (option inconnue, valeur invalide, source absente de la ligne de commande), avec l'aide sur la sortie d'erreur.
6. **La propreté.** Aucun fichier temporaire ne reste, ni dans `/tmp` ni dans la destination, même après un échec.

### les critères de réussite

Lance `bash tests.sh` aussi souvent que tu veux : il essaie ton script dans des dossiers temporaires, sans toucher à `donnees`, et affiche chaque cas réussi ou échoué.

| Test | Ce qu'il vérifie |
| --- | --- |
| aide | `-h` affiche l'aide et rend 0 |
| sans argument | rend 2 |
| option inconnue | `-z` rend 2 |
| nombre invalide | `-n abc` rend 2 |
| source absente | rend 1 et écrit `ERREUR` au journal |
| archive | une archive au bon nom, qui contient `compte rendu.txt`, et `OK` au journal |
| rotation | avec `-n 3`, trois archives de la source restent, les plus récentes, et celle d'une autre source est intacte |
| destination par défaut | sans `-d`, l'archive va dans `./sauvegardes` |
| destination impossible | une destination qui est un fichier rend 1 |
| panne de tar | avec un faux `tar` en panne placé en tête du `PATH` : le script rend 1, écrit `ERREUR` au journal, et ne laisse aucune archive |
| rien ne traîne | ni `/tmp` ni la destination ne gardent de fichier temporaire, même après une panne |

### la correction commentée

À lire après avoir essayé. Voici une solution complète, puis ses choix expliqués.

```bash
#!/bin/bash
# sauvegarde.sh : archive un dossier en .tar.gz horodaté, garde les N plus récentes,
# et note chaque exécution dans DESTINATION/sauvegarde.log.
# Usage : sauvegarde.sh [-d DESTINATION] [-n NOMBRE] [-h] SOURCE
# Codes de retour : 0 succès, 1 échec, 2 mauvaise utilisation.
set -euo pipefail

usage() {
  cat << FIN
Usage : $(basename "$0") [-d DESTINATION] [-n NOMBRE] [-h] SOURCE
  -d DESTINATION  dossier des archives (défaut : ./sauvegardes)
  -n NOMBRE       nombre d'archives à garder (défaut : 5)
  -h              affiche cette aide
FIN
}

# journal OK|ERREUR MESSAGE : une ligne horodatée dans le journal de la destination.
journal() {
  printf '%s %s %s\n' "$(date '+%F %T')" "$1" "$2" >> "$destination/sauvegarde.log"
}

# echouer MESSAGE : signale l'échec partout où il doit l'être, puis sort avec 1.
echouer() {
  echo "ERREUR : $1" >&2
  journal ERREUR "$1"
  exit 1
}

destination=./sauvegardes
garder=5
while getopts ":d:n:h" opt; do
  case "$opt" in
    d)  destination=$OPTARG ;;
    n)  garder=$OPTARG ;;
    h)  usage; exit 0 ;;
    :)  echo "L'option -$OPTARG attend une valeur." >&2; usage >&2; exit 2 ;;
    \?) echo "Option inconnue : -$OPTARG" >&2; usage >&2; exit 2 ;;
  esac
done
shift $(( OPTIND - 1 ))
if (( $# != 1 )); then
  usage >&2
  exit 2
fi
if [[ ! $garder =~ ^[0-9]+$ ]] || (( garder < 1 )); then
  echo "-n attend un nombre entier d'au moins 1, pas « $garder »." >&2
  exit 2
fi

source_dir=${1%/}
nom=$(basename "$source_dir")
mkdir -p "$destination" || exit 1
[[ -d $source_dir ]] || echouer "source introuvable : $source_dir"

archive="$destination/$nom-$(date +%Y%m%d-%H%M%S).tar.gz"
temporaire=$(mktemp)
trap 'rm -f "$temporaire"' EXIT
tar -cf - -C "$(dirname "$source_dir")" "$nom" | gzip > "$temporaire" \
  || echouer "échec de l'archivage de $source_dir"
mv "$temporaire" "$archive"
journal OK "$(basename "$archive") créée"

# Rotation : les noms portent la date, l'ordre alphabétique est l'ordre chronologique.
mapfile -t anciennes < <(printf '%s\n' "$destination/$nom"-*.tar.gz | sort -r | tail -n +$(( garder + 1 )))
if (( ${#anciennes[@]} > 0 )); then
  rm -- "${anciennes[@]}"
  journal OK "${#anciennes[@]} ancienne(s) archive(s) supprimée(s)"
fi
```

**La structure.** Le mode strict en tête, puis les fonctions, puis la lecture des options, puis le travail. Les trois fonctions évitent de répéter le même code : `journal` écrit une ligne, `echouer` fait les trois gestes d'un échec (message, journal, code 1), `usage` sert à `-h` comme aux erreurs d'utilisation. L'en-tête documente l'usage et les codes de retour, ce que les tests vérifient justement.

**Les options.** `getopts ":d:n:h"` : `-d` et `-n` attendent une valeur, le `:` de tête laisse le script gérer les erreurs, avec le code 2 et l'aide sur la sortie d'erreur. Après `shift`, il doit rester exactement un argument. La valeur de `-n` est validée par une expression régulière **avant** tout calcul : `-n abc` serait sinon devenu 0, puis une rotation qui supprime tout.

**Les noms.** Toutes les variables sont entre guillemets, ce qui fait passer `compte rendu.txt` sans encombre. `${1%/}` retire une éventuelle barre oblique finale (`donnees/` donnerait sinon un nom vide), `basename` et `dirname` découpent le chemin, et `tar -C` archive le dossier sous son seul nom, sans le chemin complet.

**L'ordre des vérifications.** La destination est créée **avant** de vérifier la source, pour que l'erreur « source introuvable » puisse être écrite dans son journal. Si la destination ne peut pas être créée, `mkdir` affiche sa propre erreur et le script sort avec 1 : il n'y a pas de journal où écrire.

**L'archive.** Elle est d'abord écrite dans un fichier temporaire créé par `mktemp`, puis déplacée à son nom définitif seulement si tout a réussi. Ainsi, une archive à moitié écrite ne porte jamais le nom d'une vraie sauvegarde. Le `trap ... EXIT`, posé juste après `mktemp`, supprime le temporaire si le script s'arrête en route. Grâce à `pipefail`, un `tar` qui échoue fait échouer le tube, même si `gzip` réussit : c'est ce que vérifie le cas « panne de tar ». Sans `pipefail`, le tube aurait réussi, et le script aurait rangé sous un vrai nom une archive vide, en écrivant `OK` au journal.

**La rotation.** Elle ne s'exécute qu'**après** une sauvegarde réussie : un script qui supprime les anciennes copies alors que la nouvelle a échoué peut finir par ne plus rien garder du tout. Le motif `"$destination/$nom"-*.tar.gz` ne vise que les archives de cette source. Les noms portant la date au format `AAAAMMJJ-HHMMSS`, le tri alphabétique inverse range les plus récentes en tête, et `tail -n +$(( garder + 1 ))` donne celles qui sont en trop. `mapfile` les range dans un tableau, et `rm -- "${anciennes[@]}"` les supprime sans risque, même avec des noms étranges.

**Le code de retour.** Sous `set -e`, le script s'arrête à la première erreur non traitée, avec un code non nul ; arrivé au bout, il rend 0. Il ne peut donc plus annoncer un succès qu'il n'a pas obtenu, ce qui était le défaut de la sauvegarde de la leçon sur la robustesse.

### pour aller plus loin

Trois améliorations, dans l'ordre où un vrai service les demanderait :

- **un verrou** : enveloppe le travail dans `flock -n` sur `/run/lock/sauvegarde.lock`, pour que deux exécutions ne se chevauchent jamais ;
- **une vérification de l'archive** : après le `mv`, relis-la avec `gunzip -t`, et calcule son empreinte avec `sha256sum` dans un fichier à côté, pour détecter plus tard une archive abîmée ;
- **la planification** : sur un serveur, installe le script dans `/usr/local/bin` en `755`, propriété de root, puis planifie-le, avec une ligne de crontab qui redirige sa sortie, ou avec un minuteur systemd `Persistent=true`. Et une sauvegarde n'existe vraiment que le jour où l'on a réussi à la **restaurer** : fais l'essai.

## à retenir

- Un script fiable commence par **`set -euo pipefail`**, documente son **usage** et ses **codes de retour**, et se découpe en **fonctions**.
- Les entrées se **valident** avant usage, les options se lisent avec **`getopts`**, une mauvaise utilisation rend **2**.
- Des **guillemets** partout : les noms de fichiers ne sont jamais aussi sages qu'on le croit.
- On écrit dans un **temporaire** (`mktemp`, nettoyé par `trap ... EXIT`), puis on le déplace : jamais d'archive à moitié écrite sous un vrai nom.
