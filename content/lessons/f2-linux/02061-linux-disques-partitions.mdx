Tout ce qu'un serveur garde, ses programmes, ses configurations, ses bases de données, ses journaux, vit sur des disques. Les modules précédents les ont traités comme une évidence : un `/` qui existe, un `df -h` qui affiche des pourcentages. Ce module descend d'un étage. On ajoute un disque à un serveur, on le découpe en partitions, on y crée un système de fichiers, on le monte, on le regroupe avec d'autres, on le chiffre, et surtout on sauvegarde ce qu'il contient. Première étape : savoir **quels disques** a la machine, et les **découper**, sans jamais se tromper de disque.

## objectifs

À la fin de cette leçon, tu sais :

- reconnaître les noms des disques et des partitions sous Linux ;
- lister les disques avec `lsblk`, `blkid` et `/dev/disk/` ;
- désigner un disque par un nom qui ne change pas ;
- expliquer les différences entre les tables de partitions **MBR** et **GPT** ;
- partitionner un disque avec `fdisk` ou `parted` ;
- choisir un découpage qui protège un serveur.

## pourquoi ça compte

Les opérations sur les disques sont parmi les plus **irréversibles** d'un administrateur. Une table de partitions écrite sur le mauvais disque, un système de fichiers créé par-dessus des données, et les sauvegardes deviennent la seule issue. La règle de cette leçon tient en une phrase : **identifier le disque avec certitude avant d'écrire quoi que ce soit dessus**. Le découpage a aussi un rôle de sécurité : un `/var` séparé empêche des journaux qui débordent de remplir la racine, et des options de montage adaptées à chaque partition, que la leçon sur le montage détaille, retirent des armes à un attaquant.

## les noms des disques

Linux représente chaque disque par un **fichier de périphérique** dans `/dev` :

| Nom | Type de disque | Ses partitions |
| --- | --- | --- |
| `/dev/sda`, `/dev/sdb`… | SATA, SAS, SCSI, USB | `/dev/sda1`, `/dev/sda2`… |
| `/dev/nvme0n1`, `/dev/nvme1n1`… | SSD NVMe | `/dev/nvme0n1p1`, `/dev/nvme0n1p2`… |
| `/dev/vda`, `/dev/vdb`… | disque virtuel d'une machine virtuelle | `/dev/vda1`… |
| `/dev/mmcblk0` | carte SD, mémoire embarquée | `/dev/mmcblk0p1`… |

Ces noms sont attribués **dans l'ordre de détection** au démarrage. Ajoute un disque, change un câble de port, et celui qui s'appelait `sdb` peut devenir `sdc`. Un script ou un `/etc/fstab` qui désigne un disque par `/dev/sdb` peut alors viser le mauvais. D'où les **noms stables** que Linux fabrique dans `/dev/disk/` :

- `/dev/disk/by-id/` : le modèle et le numéro de série du disque, gravé en usine ;
- `/dev/disk/by-uuid/` : l'identifiant unique du **système de fichiers**, créé avec lui ;
- `/dev/disk/by-path/` : le chemin physique, le port du contrôleur.

Pour un disque qu'on va effacer, on vérifie son **numéro de série** dans `by-id` ; pour monter un système de fichiers, on utilise son **UUID**.

## voir les disques

```bash
lsblk                  # l'arbre des disques, partitions, volumes, avec tailles et points de montage
lsblk -f               # avec le type de système de fichiers, l'étiquette et l'UUID
sudo blkid             # les UUID et les types, partition par partition
sudo fdisk -l          # les tables de partitions de chaque disque
ls -l /dev/disk/by-id/ # les noms stables, avec les numéros de série
```

**`lsblk`** est le premier réflexe : il montre d'un coup d'œil chaque disque, ses partitions, leur taille et l'endroit où elles sont montées. Un disque qui vient d'être ajouté se reconnaît à ce qu'il n'a ni partition ni point de montage. Une colonne `TYPE` dit s'il s'agit d'un disque (`disk`), d'une partition (`part`), d'un volume LVM (`lvm`) ou d'un volume chiffré (`crypt`), que les leçons suivantes présentent.

## MBR et GPT

Le début d'un disque contient sa **table de partitions**, qui dit où commence et où finit chaque partition. Deux formats existent :

| | MBR (ou DOS) | GPT |
| --- | --- | --- |
| Époque | 1983 | années 2000, avec l'UEFI |
| Taille maximale du disque | 2 Tio | 8 Zio, sans limite pratique |
| Nombre de partitions | 4 principales, ou 3 et une étendue qui en contient d'autres | 128 par défaut |
| Copie de secours | aucune | une seconde table à la fin du disque, et une somme de contrôle |
| Démarrage | BIOS | UEFI, avec une partition système EFI |

Le **MBR** tient dans le premier secteur du disque, 512 octets, avec une seule copie : une écriture accidentelle sur ce secteur perd toute la table. Ses limites, quatre partitions et deux tébioctets, viennent d'une époque où les disques faisaient quelques dizaines de mégaoctets. **GPT** les lève toutes, garde une copie de secours et vérifie l'intégrité de sa table. Sur une machine récente et pour tout disque de plus de 2 Tio, c'est **GPT**, sans hésitation. Le MBR reste utile pour de petits supports, comme une clé USB que doit lire un vieux système.

## partitionner : fdisk et parted

**`fdisk`** est interactif : on lui donne un disque, et il attend des commandes d'une lettre. Les principales : `p` affiche la table, `n` crée une partition, `d` en supprime une, `t` change son type, `g` crée une table GPT vide, `o` une table MBR vide, `w` **écrit** et quitte, `q` quitte **sans rien écrire**. Tant qu'on n'a pas tapé `w`, rien n'est modifié sur le disque : on peut tout essayer, et sortir par `q`.

**`parted`** fait la même chose, en ligne de commande, ce qui le rend pratique dans un script :

```bash
sudo parted /dev/sdb --script mklabel gpt mkpart donnees ext4 1MiB 100%
sudo parted /dev/sdb print
```

Cette ligne crée une table GPT, puis une partition qui va de 1 Mio jusqu'à la fin du disque. Commencer à **1 Mio** aligne la partition sur les blocs physiques des disques modernes et des SSD ; un mauvais alignement peut diviser les performances par deux. Les outils actuels le font tout seuls. Après une modification, si le noyau ne voit pas encore la nouvelle partition, `sudo partprobe /dev/sdb` lui fait relire la table.

Chaque partition porte un **type**, qui dit à quoi elle sert : `Linux` (83 en MBR) pour des données, `Linux swap` (82) pour l'espace d'échange, `EFI System` pour la partition de démarrage UEFI, `Linux LVM` (8e) pour un volume LVM. Le type n'empêche rien, mais il aide les outils et les humains à comprendre le disque.

## découper un serveur

Une installation par défaut met souvent tout dans une seule partition `/`. C'est simple, mais un seul dossier qui déborde remplit tout le système. Les guides de durcissement, dont celui de l'ANSSI, recommandent de **séparer** au moins :

- `/boot` et la partition EFI, pour le démarrage ;
- `/` pour le système ;
- `/var`, et souvent `/var/log` à part, car journaux et données y grossissent sans prévenir ;
- `/home`, pour les données des utilisateurs ;
- `/tmp`, que tout le monde peut écrire ;
- l'espace d'échange, en partition ou en fichier.

Chaque partition séparée a deux avantages : un dossier plein n'arrête plus la machine entière, et chacune peut être montée avec des **options** propres, comme l'interdiction d'exécuter des programmes dans `/tmp`. Les leçons sur le montage et sur LVM montreront comment le faire sans figer définitivement les tailles.

## l'espace d'échange

L'**espace d'échange** (*swap*) reçoit les pages de mémoire que le noyau retire de la mémoire vive quand elle vient à manquer. Il peut vivre dans une **partition** dédiée, de type `Linux swap`, ou dans un simple **fichier**, plus facile à agrandir ou à supprimer : c'est le choix par défaut d'Ubuntu. Sa taille dépend de l'usage : quelques gigaoctets suffisent à un serveur, qui ne doit de toute façon pas vivre en manquant de mémoire, alors qu'un portable qui hiberne a besoin d'au moins autant que sa mémoire vive. Comme il peut contenir n'importe quelle donnée passée par la mémoire, mots de passe compris, on le chiffre avec le reste du disque.

## à toi de jouer

Le Linux des exercices n'a pas de vrai disque, mais `fdisk` sait travailler sur un **fichier image**, exactement comme sur un disque. Fabrique-en un, et partitionne-le :

1. crée une image de 8 Mo remplie de zéros : `dd if=/dev/zero of=disque.img bs=64k count=128` ;
2. ouvre-la avec `fdisk disque.img`, puis tape, une par une, les commandes de `fdisk` :
   - `o` : une nouvelle table MBR, vide ;
   - `n`, puis `p`, puis `1` : une partition principale numéro 1. Garde le premier secteur proposé (Entrée), et donne `+4M` comme fin ;
   - `n`, `p`, `2` : une seconde partition. Entrée deux fois : elle prend tout le reste ;
   - `t`, puis `2`, puis `82` : la seconde partition devient de type `Linux swap` ;
   - `p` pour relire la table, puis `w` pour l'écrire et quitter ;
3. vérifie et garde le résultat : `fdisk -l disque.img > table.txt`, puis `cat table.txt`.

Remarque le premier secteur proposé par ce `fdisk` minimal : 63, l'ancien alignement des disques des années 1990. Les `fdisk` et `parted` d'une distribution actuelle proposent 2048, c'est-à-dire 1 Mio. Et rien n'a été écrit dans l'image avant le `w` : c'est le moment de relire la table avec `p`, sur un vrai disque surtout. L'avertissement affiché après le `w`, `rereading partition table failed`, est normal ici : `fdisk` a demandé au noyau de relire la table, ce qui n'a pas de sens pour un fichier. Sur un vrai disque en cours d'utilisation, le même message voudrait dire que le noyau continue d'utiliser l'ancienne table jusqu'au prochain démarrage, ou jusqu'à un `partprobe` réussi.

## les pièges

- **Écrire sur le mauvais disque.** `lsblk` et le numéro de série dans `/dev/disk/by-id/` avant toute écriture.
- **Désigner un disque par `/dev/sdb` dans un script ou dans `fstab`.** Le nom peut changer au prochain démarrage : UUID ou `by-id`.
- **Utiliser le MBR sur un disque de plus de 2 Tio.** L'espace au-delà est inutilisable : GPT.
- **Partitionner un disque monté.** Le noyau ne relit pas la table d'un disque en cours d'utilisation, et les données peuvent être corrompues.
- **Taper `w` sans avoir relu avec `p`.** C'est la dernière occasion de corriger.
- **Tout mettre dans `/`.** Un journal qui déborde arrête alors le serveur entier.

## à retenir

- Les disques : **`/dev/sda`**, **`/dev/nvme0n1`**, **`/dev/vda`** ; leurs partitions : `sda1`, `nvme0n1p1`. Ces noms peuvent changer.
- Des noms stables dans **`/dev/disk/by-uuid/`** et **`by-id/`** ; on vérifie le numéro de série avant d'écrire.
- **`lsblk`** (et `-f`), **`blkid`**, **`fdisk -l`** pour voir.
- **MBR** : 4 partitions, 2 Tio, une seule copie. **GPT** : 128 partitions, aucune limite pratique, une copie de secours.
- **`fdisk`** interactif, rien n'est écrit avant **`w`** ; **`parted --script`** pour les scripts ; partitions alignées sur **1 Mio**.
- Un serveur sépare **`/`**, **`/var`**, **`/home`**, **`/tmp`** : un dossier plein n'arrête plus tout.
