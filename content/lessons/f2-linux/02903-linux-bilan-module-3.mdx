Le module 3 t'a donné la boîte à outils du texte : rediriger les flux, enchaîner les commandes, filtrer avec `grep`, décrire des formes avec les expressions régulières, couper, trier et compter, transformer avec `sed`, calculer avec `awk`, comparer avec `diff` et `comm`. Ce bilan vérifie les connaissances, puis te fait produire un vrai livrable : le rapport d'activité d'un site web, tiré de son journal d'accès, le genre de document qu'on demande à un administrateur chaque lundi matin, ou à un analyste après un incident.

## objectifs

Ce bilan valide que tu sais :

- séparer résultats et erreurs, et écrire un rapport dans un fichier ;
- construire une chaîne de commandes étape par étape ;
- extraire des informations précises d'un journal avec `grep`, `cut` et `awk` ;
- compter, classer et agréger avec `sort`, `uniq` et les tableaux d'`awk` ;
- générer un document lisible à partir de plusieurs commandes.

## projet

### la situation

Ton responsable te demande, chaque lundi, un rapport d'activité du site de l'entreprise : combien de requêtes, qui les fait, avec quel résultat, quelles pages posent problème, à quelles heures le site est le plus chargé. Tu vas le produire à partir du journal d'accès, uniquement avec les outils du module.

### générer le journal

Pour travailler sur des données réalistes sans serveur web, génère un journal d'accès fictif de 5 000 lignes au format de nginx. La commande ci-dessous est un petit programme `awk` : relis-le, tu en comprends maintenant chaque élément (`BEGIN`, tableaux, boucle, `printf`).

```bash
awk 'BEGIN {
  srand(42)
  split("203.0.113.42 198.51.100.7 192.0.2.10 203.0.113.77 198.51.100.23", ips, " ")
  split("/ /accueil /recherche /api/commande /compte /admin", pages, " ")
  split("200 200 200 200 304 404 500 502", codes, " ")
  for (i = 1; i <= 5000; i++) {
    ip = ips[int(rand() * 5) + 1]
    page = pages[int(rand() * 6) + 1]
    code = codes[int(rand() * 8) + 1]
    printf "%s - - [27/Sep/2026:%02d:%02d:00 +0200] \"GET %s HTTP/1.1\" %s %d \"-\" \"Mozilla/5.0\"\n", ip, int(rand() * 24), int(rand() * 60), page, code, int(rand() * 50000)
  }
}' > ~/access.log
```

`srand(42)` fixe le point de départ du générateur aléatoire : avec la même version d'`awk`, tout le monde obtient exactement le même journal. Les chiffres peuvent varier légèrement d'une implémentation à l'autre (`gawk`, `mawk`), mais pas la forme des résultats, et les critères de réussite n'en dépendent pas.

### le cahier des charges

Le rapport, un fichier texte `~/rapport-AAAA-MM-JJ.txt` daté du jour par une commande, doit contenir dans cet ordre :

1. **Le volume** : le nombre total de requêtes, et le volume servi en mégaoctets, avec une décimale.
2. **Les cinq adresses les plus actives**, avec leur nombre de requêtes, de la plus active à la moins active.
3. **La répartition des codes HTTP**, du plus fréquent au moins fréquent.
4. **Les pages en erreur serveur** (codes 5xx), avec leur nombre d'erreurs, de la plus touchée à la moins touchée.
5. **Le trafic par heure**, de 00 à 23, dans l'ordre des heures.

Chaque partie commence par un titre. Les éventuels messages d'erreur des commandes ne doivent **pas** se retrouver dans le rapport, mais dans un fichier `~/rapport-erreurs.log`.

### les critères de réussite

| Vérification | Résultat attendu |
| --- | --- |
| `ls ~/rapport-*.txt` | Un fichier daté du jour |
| Partie 1 | 5000 requêtes, et un volume cohérent avec `awk` sur le dixième champ |
| Partie 2 | Cinq lignes, triées par nombre décroissant |
| Partie 3 | Les cinq codes du journal (200, 304, 404, 500, 502), triés par fréquence : 200 en tête |
| Partie 4 | Uniquement des pages, avec des comptes qui ne concernent que 500 et 502 |
| Partie 5 | Vingt-quatre lignes au plus, de 00 à 23 dans l'ordre |
| `cat ~/rapport-erreurs.log` | Vide si tout s'est bien passé |

### la correction commentée

À lire après avoir essayé. Construis chaque chaîne étape par étape, avec `| head`, avant de l'intégrer au rapport.

**Le nom du fichier**, calculé une fois et gardé dans une variable :

```bash
rapport=~/rapport-$(date +%F).txt
journal=~/access.log
```

**Partie 1 : le volume.** `wc -l` avec une redirection d'entrée pour avoir le nombre seul, et `awk` pour la somme des octets :

```bash
echo "== Volume ==" > "$rapport"
echo "Requêtes : $(wc -l < "$journal")" >> "$rapport"
awk '{ o += $10 } END { printf "Volume servi : %.1f Mo\n", o / 1048576 }' "$journal" >> "$rapport"
```

Le premier `echo` utilise `>` pour créer le rapport à neuf ; tous les suivants utilisent `>>` pour ajouter.

**Partie 2 : les adresses.** La recette classique :

```bash
echo "== Adresses les plus actives ==" >> "$rapport"
cut -d ' ' -f 1 "$journal" | sort | uniq -c | sort -rn | head -5 >> "$rapport"
```

**Partie 3 : les codes.** Le code de statut est le neuvième champ :

```bash
echo "== Codes HTTP ==" >> "$rapport"
awk '{ print $9 }' "$journal" | sort | uniq -c | sort -rn >> "$rapport"
```

**Partie 4 : les pages en erreur serveur.** On filtre sur le code avec `awk` et un motif ancré, plutôt qu'avec un `grep` qui pourrait trouver un 5 ailleurs dans la ligne, puis on compte par page, le septième champ :

```bash
echo "== Pages en erreur serveur ==" >> "$rapport"
awk '$9 ~ /^5/ { n[$7]++ } END { for (p in n) print n[p], p }' "$journal" | sort -rn >> "$rapport"
```

**Partie 5 : le trafic par heure.** L'heure est dans le quatrième champ, `[27/Sep/2026:14:37:00` : on la découpe sur les deux-points, c'est le deuxième morceau. Puis on trie **par heure** et non par nombre :

```bash
echo "== Trafic par heure ==" >> "$rapport"
cut -d ':' -f 2 "$journal" | sort | uniq -c | awk '{ print $2 "h : " $1 }' >> "$rapport"
```

Ici, pas de `sort -rn` final : le tri alphabétique de `sort` range déjà `00` à `23` dans l'ordre, grâce au zéro initial produit par `%02d`.

**Les erreurs à part.** Pour que les messages d'erreur éventuels aillent dans leur propre fichier, on peut regrouper toutes les commandes et rediriger leur sortie d'erreur une seule fois. Enregistre les commandes ci-dessus dans un fichier `rapport.sh`, puis lance :

```bash
bash rapport.sh 2> ~/rapport-erreurs.log
cat ~/rapport-$(date +%F).txt
```

Un fichier d'erreurs vide et un rapport complet : c'est terminé. Au passage, tu viens d'écrire ton premier script de production de rapport ; au module 7, tu le rendras paramétrable (le journal et la date en arguments), robuste (`set -euo pipefail`) et planifiable pour qu'il arrive tout seul chaque lundi.

### pour aller plus loin

Ajoute deux parties au rapport : les **adresses qui ont tenté d'accéder à `/admin`**, avec leur nombre de tentatives, et la **comparaison avec la semaine précédente** : génère un second journal avec `srand(7)`, produis les deux listes d'adresses triées, et utilise `comm` pour lister les adresses nouvelles cette semaine.

## à retenir

- Un rapport se construit partie par partie : `>` pour créer, `>>` pour ajouter, `2>` pour tenir les erreurs à l'écart.
- Chaque question est une chaîne : extraire (`cut`, `awk`), filtrer (`grep`, motif `awk` ancré), compter (`sort | uniq -c`), classer (`sort -rn`), limiter (`head`).
- `awk` et ses tableaux quand il faut agréger par clé ou calculer ; `cut` quand une colonne suffit.
- Un motif ancré sur le bon champ (`$9 ~ /^5/`) est plus sûr qu'un `grep` sur toute la ligne.
- Le module 4 passe des fichiers à leurs propriétaires : utilisateurs, groupes et permissions.
