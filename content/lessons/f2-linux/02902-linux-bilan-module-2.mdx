Le module 2 t'a donné la carte du système et tous les outils pour y travailler : se déplacer, créer, copier, déplacer, supprimer, désigner des groupes de fichiers, comprendre les liens, chercher dans toute une arborescence, archiver, et lire les métadonnées. Ce bilan vérifie les connaissances, puis te met dans une situation que tout administrateur rencontre : un serveur en désordre, à remettre d'aplomb sans rien perdre d'important.

## objectifs

Ce bilan valide que tu sais :

- situer n'importe quel fichier dans la hiérarchie standard et savoir ce qui se sauvegarde ;
- manipuler fichiers et répertoires avec les options qui protègent ;
- prévisualiser ce que désigne un joker avant d'agir ;
- trouver des fichiers selon plusieurs critères et agir sur eux en sécurité ;
- créer une archive restaurable et vérifier ce qu'elle contient ;
- lire les métadonnées d'un fichier pour décider quoi en faire.

## projet

### la situation

Tu reprends un serveur d'application laissé en désordre par l'équipe précédente. Tout se passe dans un répertoire d'exercice que tu vas créer toi-même, pour pouvoir le refaire autant de fois que nécessaire sans rien risquer sur un vrai système.

### préparer le terrain

Crée le répertoire d'exercice et les fichiers de départ avec ces commandes. Lis-les avant de les exécuter : tu dois pouvoir expliquer chacune.

```bash
mkdir -p ~/serveur/{app/releases/v1,app/releases/v2,logs,uploads,tmp}
touch ~/serveur/app/releases/v1/index.html ~/serveur/app/releases/v2/index.html
ln -s ~/serveur/app/releases/v1 ~/serveur/app/current
for i in 1 2 3 4 5 6; do echo "journal $i" > ~/serveur/logs/app.log.$i; done
touch -d "40 days ago" ~/serveur/logs/app.log.{4,5,6}
head -c 5M /dev/urandom > ~/serveur/uploads/video-brute.mp4
touch ~/serveur/uploads/{photo1,photo2}.jpg ~/serveur/tmp/{a,b,c}.tmp
touch -d "10 days ago" ~/serveur/tmp/{a,b}.tmp
```

La boucle `for` crée six journaux ; le module 7 expliquera sa syntaxe. `/dev/urandom` fournit des octets aléatoires, et `head -c 5M` en garde 5 Mo : de quoi simuler un gros fichier.

### le cahier des charges

1. **Basculer l'application** sur la version `v2` : le lien `current` doit désigner `releases/v2`, sans supprimer `v1`.
2. **Archiver les vieux journaux** : ceux de `logs/` non modifiés depuis plus de 30 jours vont dans une archive compressée `~/archives/logs-AAAA-MM-JJ.tar.gz` (la date du jour, obtenue par une commande, pas tapée à la main), puis sont supprimés de `logs/`.
3. **Repérer les gros fichiers** : liste, dans un fichier `~/rapport-gros-fichiers.txt`, les fichiers de plus de 1 Mo de tout `~/serveur`.
4. **Nettoyer le temporaire** : supprime de `tmp/` les fichiers `.tmp` de plus de 7 jours, **et eux seuls**.
5. **Vérifier l'archive** sans l'extraire, puis restaurer un seul des journaux archivés dans `~/restauration/` pour prouver que l'archive est utilisable.

### les critères de réussite

| Vérification | Résultat attendu |
| --- | --- |
| `readlink ~/serveur/app/current` | Se termine par `releases/v2` |
| `ls ~/serveur/app/releases` | `v1` et `v2` sont toujours là |
| `ls ~/serveur/logs` | Seulement `app.log.1`, `app.log.2`, `app.log.3` |
| `tar -tzf ~/archives/logs-*.tar.gz` | Les trois anciens journaux, et rien d'autre |
| `cat ~/rapport-gros-fichiers.txt` | Le chemin de `video-brute.mp4` |
| `ls ~/serveur/tmp` | Seulement `c.tmp` |
| `ls ~/restauration` | Contient un journal restauré depuis l'archive |

### la correction commentée

À lire après avoir essayé. D'autres solutions sont valables si les critères passent.

**1. La bascule**, avec `-sfn` pour remplacer un lien vers un répertoire sans créer de lien à l'intérieur :

```bash
ln -sfn ~/serveur/app/releases/v2 ~/serveur/app/current
readlink ~/serveur/app/current
```

**2. Les vieux journaux.** On les désigne avec `find`, on regarde avant d'agir, puis on archive en donnant la liste à `tar` :

```bash
find ~/serveur/logs -type f -mtime +30
mkdir -p ~/archives
tar -czf ~/archives/logs-$(date +%F).tar.gz -C ~/serveur/logs \
    $(cd ~/serveur/logs && find . -type f -mtime +30)
```

`-C ~/serveur/logs` enregistre des chemins relatifs à `logs/`, sans le chemin complet de ton répertoire personnel ; la substitution de commande fournit la liste des fichiers vus juste avant. Puis on vérifie l'archive **avant** de supprimer les originaux :

```bash
tar -tzf ~/archives/logs-$(date +%F).tar.gz
find ~/serveur/logs -type f -mtime +30 -delete
```

L'ordre compte : archiver, vérifier, **puis** supprimer. Supprimer d'abord, c'est parier sur une archive qu'on n'a pas regardée.

**3. Les gros fichiers**, dans un fichier grâce à la redirection `>` (module 3) :

```bash
find ~/serveur -type f -size +1M > ~/rapport-gros-fichiers.txt
```

**4. Le temporaire**, en combinant nom et âge, avec la vérification préalable habituelle :

```bash
find ~/serveur/tmp -type f -name "*.tmp" -mtime +7
find ~/serveur/tmp -type f -name "*.tmp" -mtime +7 -delete
```

`c.tmp`, créé aujourd'hui, reste en place : le critère d'âge le protège.

**5. La restauration** d'un seul fichier, dans un répertoire neutre :

```bash
mkdir -p ~/restauration
tar -xzf ~/archives/logs-$(date +%F).tar.gz -C ~/restauration ./app.log.4
cat ~/restauration/app.log.4
```

Le nom à extraire s'écrit exactement comme dans la liste de `tar -t`, ici avec le `./` initial produit par `find .`.

### pour aller plus loin

Refais tout l'exercice en écrivant les commandes des étapes 2 à 4 dans un fichier texte, que tu relis ligne par ligne avant de l'exécuter avec `bash` : c'est un premier script de maintenance. Au module 7, tu le rendras robuste, paramétrable et planifiable.

## à retenir

- La hiérarchie standard dit où chercher et quoi sauvegarder ; `/var` est ce qui remplit les disques.
- Avant d'agir sur un groupe de fichiers : `echo` ou `ls` avec le même motif, ou `find` sans action.
- Archiver, **vérifier l'archive**, puis seulement supprimer les originaux. Restaurer dans un répertoire neutre.
- `find` combine nom, type, taille, âge, droits ; `-delete` toujours en dernier.
- Les liens symboliques basculent une version en une commande ; les métadonnées révèlent l'âge et la nature réelle d'un fichier.
- Le module 3 t'apprend à traiter le contenu des fichiers : filtrer, transformer, et enchaîner les commandes.
