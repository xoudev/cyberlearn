Le module 6 t'a appris d'où viennent les logiciels d'un Linux et comment les gérer : les paquets et leurs dépendances, les commandes du quotidien, les dépôts et leur chaîne de signatures, les mises à jour, la compilation, et les formats qui vivent en dehors des paquets. Ce bilan vérifie les connaissances, puis te fait préparer un serveur de bout en bout, comme on le fait avant de le mettre en service : un système à jour, les bons logiciels depuis les bonnes sources, rien de superflu, des correctifs automatiques, et un inventaire.

## objectifs

Ce bilan valide que tu sais :

- mettre à jour un système et savoir s'il faut redémarrer ;
- installer depuis les dépôts officiels sans rien embarquer d'inutile ;
- retirer proprement ce qui ne sert pas ;
- ajouter un dépôt tiers avec sa clé, limitée à ce dépôt, et vérifier d'où vient un paquet ;
- activer les mises à jour de sécurité automatiques ;
- dresser l'inventaire de ce qui est installé, y compris hors des paquets.

## projet

### la situation

Ton équipe reçoit un serveur Debian 12 fraîchement installé, qui hébergera une petite application web et sa base de données PostgreSQL. Il faut le préparer avant la mise en service. Ce projet demande les droits root et un accès à Internet : fais-le dans la **machine virtuelle d'entraînement** installée au parcours Fondamentaux, **jamais sur un serveur réel**.

### le cahier des charges

1. Le système est **à jour**, et redémarré si nécessaire.
2. Sont installés **depuis les dépôts officiels**, sans leurs recommandations : `nginx`, `curl`, `git` et `unattended-upgrades`.
3. Aucun client en clair ne traîne : si `telnet` ou `ftp` sont présents, ils sont **purgés**, et les dépendances orphelines retirées.
4. **PostgreSQL 16** est installé depuis le **dépôt officiel du projet PostgreSQL**, déclaré au format deb822, avec sa clé dans `/etc/apt/keyrings/` et l'option `Signed-By`.
5. Les **mises à jour de sécurité** s'installent automatiquement chaque jour.
6. Un **inventaire** est écrit dans `/root/inventaire-logiciels.txt` : les paquets installés à la main, les dépôts déclarés, et les exécutables de `/usr/local/bin` qui n'appartiennent à aucun paquet.

### les critères de réussite

| Test | Résultat attendu |
| --- | --- |
| `apt list --upgradable` | Aucun paquet |
| `ls /var/run/reboot-required` | Fichier absent |
| `apt-mark showmanual` | Contient `nginx`, `curl`, `git`, `unattended-upgrades` |
| `dpkg -l telnet` | Aucun paquet, ou aucun en état `ii` ni `rc` |
| `apt-cache policy postgresql-16` | Version installée venant de `apt.postgresql.org` |
| `grep -r trusted /etc/apt/sources.list*` | Aucun résultat |
| `cat /etc/apt/apt.conf.d/20auto-upgrades` | `APT::Periodic::Unattended-Upgrade "1";` |
| `systemctl is-enabled apt-daily-upgrade.timer` | `enabled` |
| `cat /root/inventaire-logiciels.txt` | Les trois parties du point 6 |

### la correction commentée

À lire après avoir essayé.

**1. Mettre à jour, puis vérifier s'il faut redémarrer :**

```bash
sudo apt update
sudo apt full-upgrade
ls /var/run/reboot-required && cat /var/run/reboot-required.pkgs
sudo reboot
```

Sur un système neuf, `full-upgrade` est approprié, à condition de lire sa liste. Le redémarrage n'a lieu que si le fichier existe.

**2 et 3. Installer le nécessaire, retirer le superflu :**

```bash
sudo apt install --no-install-recommends nginx curl git unattended-upgrades
sudo apt purge telnet ftp
sudo apt autoremove
```

Si `telnet` ou `ftp` sont absents, `apt` le dit et continue sans erreur grave. Lis la liste d'`autoremove` avant de valider.

**4. Le dépôt de PostgreSQL**, en suivant la méthode de la leçon sur les dépôts :

```bash
sudo install -d /etc/apt/keyrings
sudo curl -fsSL -o /etc/apt/keyrings/postgresql.asc https://www.postgresql.org/media/keys/ACCC4CF8.asc
gpg --show-keys /etc/apt/keyrings/postgresql.asc
```

Compare l'empreinte affichée à celle que publie la page de téléchargement de postgresql.org pour Debian. Puis déclare le dépôt dans `/etc/apt/sources.list.d/pgdg.sources` :

```text
Types: deb
URIs: https://apt.postgresql.org/pub/repos/apt
Suites: bookworm-pgdg
Components: main
Signed-By: /etc/apt/keyrings/postgresql.asc
```

```bash
sudo apt update
apt-cache policy postgresql-16
sudo apt install postgresql-16
```

`apt-cache policy`, lancé **avant** l'installation, confirme que la version candidate vient bien de `apt.postgresql.org` : c'est la preuve que le dépôt est pris en compte, et le seul endroit d'où ce paquet pouvait venir.

**5. Les mises à jour automatiques :**

```bash
sudo dpkg-reconfigure -plow unattended-upgrades
sudo unattended-upgrades --dry-run --debug | tail -5
```

La première commande écrit le fichier `/etc/apt/apt.conf.d/20auto-upgrades`, qui active le passage quotidien, déclenché par le minuteur systemd `apt-daily-upgrade.timer` ; la seconde simule un passage pour vérifier la configuration sans rien installer.

**6. L'inventaire :**

```bash
{
  echo "== Paquets installés à la main"; apt-mark showmanual
  echo "== Dépôts déclarés"; grep -rh '^URIs\|^deb ' /etc/apt/sources.list /etc/apt/sources.list.d/ 2>/dev/null
  echo "== Hors paquet dans /usr/local/bin"
  for f in /usr/local/bin/*; do [ -e "$f" ] || continue; dpkg -S "$f" > /dev/null 2>&1 || echo "$f"; done
} | sudo tee /root/inventaire-logiciels.txt
```

Les accolades regroupent les commandes pour n'écrire qu'une fois dans le fichier, et `sudo tee` écrit en root, comme vu au module 3. Le test `[ -e "$f" ]` évite une fausse ligne quand `/usr/local/bin` est vide.

**La preuve.** Lance chaque test du tableau. Un test qui échoue désigne précisément l'étape à reprendre.

## à retenir

- Préparer un serveur : **mettre à jour**, **installer le nécessaire** sans recommandations, **retirer le superflu**, **activer les correctifs automatiques**, **inventorier**.
- Un dépôt tiers s'ajoute avec **sa clé** dans `/etc/apt/keyrings/`, **vérifiée**, liée par **`Signed-By`**, et **`apt-cache policy`** prouve d'où vient le paquet.
- Tout ce qui est installé **hors paquet** doit figurer dans un **inventaire**, sinon personne ne le mettra à jour.
- Chaque exigence se **prouve** par une commande : c'est ce qui distingue une préparation d'un « ça a l'air de marcher ».
- Le module 7 passe aux **scripts Bash**, pour automatiser tout cela.
