Ce bilan vérifie que tout tient ensemble, puis te fait construire quelque chose de durable : l'environnement dans lequel tu travailleras pendant le reste du parcours.

## objectifs

Ce bilan valide que tu sais :

- identifier une machine et le shell qui tourne dessus ;
- lire et écrire correctement une commande, y compris avec des noms de fichiers piégés ;
- trouver de l'aide sans quitter le terminal ;
- régler ton environnement de façon permanente, dans le bon fichier ;
- modifier un fichier de configuration avec méthode.

## projet

### l'énoncé

Tu vas configurer ton environnement de travail pour le reste du parcours. Tout se fait dans ton répertoire personnel, sans droits d'administrateur, sur n'importe quelle machine Linux : une machine virtuelle, un WSL sous Windows, ou le terminal Linux du parcours dès qu'il sera disponible.

### le cahier des charges

1. **Un répertoire pour tes scripts.** Crée `~/bin`, et fais en sorte qu'il soit dans ton `PATH` à chaque connexion, **en tête**, sans perdre les autres répertoires.
2. **Un éditeur par défaut.** `EDITOR` et `VISUAL` valent l'éditeur de ton choix (nano ou vim), pour tous les programmes que tu lances.
3. **Un historique utile et sûr.** Au moins 10 000 commandes gardées en mémoire et dans le fichier, les doublons consécutifs et les lignes commençant par une espace ignorés, et l'historique ajouté au fichier plutôt qu'écrasé.
4. **Trois alias** : `ll` pour `ls -lh`, `la` pour `ls -lah`, et `..` pour remonter d'un répertoire.
5. **Une invite qui renseigne.** Elle affiche l'utilisateur, la machine et le répertoire courant, comme aujourd'hui, et elle reste sur une seule ligne.
6. **Un premier script dans `~/bin`**, nommé `qui-suis-je`, qui affiche en trois lignes : ton nom d'utilisateur, la distribution (le champ `PRETTY_NAME` de `/etc/os-release`) et la version du noyau. Il doit se lancer en tapant simplement `qui-suis-je`, depuis n'importe quel répertoire.

### les critères de réussite

Ouvre un **nouveau** terminal (ou reconnecte-toi), puis vérifie chaque point. Tous doivent passer.

| Vérification | Résultat attendu |
| --- | --- |
| `echo $PATH` | Commence par `/home/ton-nom/bin:` et contient toujours `/usr/bin` |
| `printenv EDITOR` | Le nom de ton éditeur |
| `echo $HISTSIZE $HISTFILESIZE` | Deux nombres d'au moins 10000 |
| `echo $HISTCONTROL` | `ignoreboth` |
| `shopt histappend` | `histappend      on` |
| `type ll` | Indique que `ll` est un alias de `ls -lh` |
| `cd /etc && ..` puis `pwd` | `/` |
| `cd /tmp && qui-suis-je` | Trois lignes : utilisateur, distribution, noyau |

### la correction commentée

Ne la lis qu'après avoir essayé. Il y a d'autres solutions valables : ce qui compte, c'est que les critères passent et que tu saches expliquer chaque ligne.

**Dans `~/.profile`**, lu à la connexion, les variables d'environnement :

```bash
# Mes scripts d'abord, puis les répertoires du système
export PATH="$HOME/bin:$PATH"

# L'éditeur que lancent crontab -e, sudoedit, git...
export EDITOR=nano
export VISUAL=nano
```

Pourquoi `~/.profile` : ces variables doivent être exportées une fois à la connexion et héritées par tous les programmes. Les mettre dans `~/.bashrc` marcherait aussi dans un terminal, mais le `PATH` grossirait à chaque shell imbriqué, puisque chaque `bash` relirait la ligne et ajouterait `~/bin` une fois de plus.

**Dans `~/.bashrc`**, lu par chaque shell interactif, les réglages du shell. Sur Debian et Ubuntu, le fichier existe déjà et contient des réglages d'historique : **modifie** les lignes existantes plutôt que d'en ajouter des doublons, qui prêteraient à confusion.

```bash
# Historique : long, sans doublons ni lignes commençant par une espace,
# ajouté au fichier au lieu de l'écraser
HISTSIZE=10000
HISTFILESIZE=10000
HISTCONTROL=ignoreboth
shopt -s histappend

# Alias
alias ll='ls -lh'
alias la='ls -lah'
alias ..='cd ..'
```

`HISTSIZE` et `HISTFILESIZE` n'ont pas besoin d'`export` : seul bash les lit, aucun programme enfant. Les alias entre guillemets simples, parce que leur contenu doit être pris tel quel.

**L'invite** : celle de Debian est déjà définie dans `~/.bashrc` par une ligne `PS1=...`, qui affiche `\u@\h:\w\$` (utilisateur, machine, répertoire, puis `$` ou `#`). Le critère 5 est donc rempli sans rien changer. Si tu veux la personnaliser, c'est cette ligne qu'on modifie, et `man bash`, section PROMPTING, liste tous les codes possibles.

**Le script `~/bin/qui-suis-je`**, à créer avec ton éditeur :

```bash
#!/bin/bash
# Affiche qui je suis, sur quelle distribution et quel noyau.
whoami
grep '^PRETTY_NAME=' /etc/os-release | cut -d '"' -f 2
uname -r
```

Puis on le rend exécutable :

```bash
chmod +x ~/bin/qui-suis-je
```

La première ligne, le *shebang*, dit quel programme doit interpréter le script ; `chmod +x` l'autorise à être exécuté. Tu verras ces deux points en détail aux modules 4 et 7. La ligne `grep ... | cut ...` extrait la valeur entre guillemets du champ `PRETTY_NAME` : c'est un avant-goût du module 3.

**Pourquoi il faut rouvrir un terminal** : les fichiers de démarrage ne sont relus qu'au démarrage d'un shell. `source ~/.bashrc` applique les alias tout de suite, mais le `PATH` de `~/.profile` n'est lu qu'à la connexion. Rouvrir une session, c'est aussi la seule vraie preuve que la configuration tient.

### pour aller plus loin

Si tout passe, deux améliorations utiles : afficher le code de retour de la dernière commande dans l'invite quand il n'est pas 0, et versionner tes fichiers de configuration avec Git dès que tu l'auras appris, pour retrouver ton environnement sur n'importe quelle machine en une commande.

## à retenir

- Tu sais maintenant identifier une machine, parler au shell avec une syntaxe exacte, trouver de l'aide sur place, travailler sans retaper, et régler ton environnement.
- Les réglages permanents se répartissent : variables d'environnement dans `~/.profile`, alias, invite et historique dans `~/.bashrc`.
- Une configuration se vérifie dans une **nouvelle** session : c'est la seule preuve qu'elle tient.
- Le module 2 te fait parcourir et manipuler le système de fichiers, en t'appuyant sur tout ce qui précède.
