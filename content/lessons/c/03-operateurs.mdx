Calculer et comparer, c'est presque tout ce que fait un programme au quotidien. On additionne des montants, on vérifie si un utilisateur a l'âge requis, on regarde si un compteur a atteint sa limite. Tout ça passe par des opérateurs. Un opérateur prend une ou deux valeurs et en produit une nouvelle. L'ensemble forme une expression, et une expression a toujours une valeur.

En C, la plupart des opérateurs se comportent comme on l'attend. Mais deux ou trois règles surprennent quand on débute, et la division entière est probablement celle qui fait perdre le plus de temps. On va la voir en détail.

## arithmétique de base

Commençons par ce qui ne réserve aucune surprise. Les quatre opérations habituelles existent telles quelles : `+` pour additionner, `-` pour soustraire, `*` pour multiplier, `/` pour diviser. Les priorités sont celles des maths : la multiplication et la division passent avant l'addition et la soustraction, et on peut forcer l'ordre avec des parenthèses.

<CodePlayground language="c" starterCode={`\`\`\`c
#include <stdio.h>

int main(void) {
    int a = 10;
    int b = 3;

    printf("Somme       : %d\\n", a + b);
    printf("Difference  : %d\\n", a - b);
    printf("Produit     : %d\\n", a * b);
    printf("Avec parentheses : %d\\n", (a + b) * 2);

    return 0;
}
\`\`\``} />

Jusque-là, rien d'étonnant. C'est avec la division que les choses se compliquent.

## la division entière

Voici la règle qui surprend tout le monde au moins une fois. Quand vous divisez deux entiers en C, le résultat est lui aussi un entier. La partie après la virgule n'est pas arrondie, elle est coupée. Purement supprimée.

Donc `7 / 2` ne vaut pas `3.5`. Ça vaut `3`. Le `.5` disparaît. De même, `5 / 2` vaut `2`, et `1 / 3` vaut `0`.

Pourquoi ce comportement ? Parce que `7` et `2` sont des `int`, et que le type du résultat dépend du type des opérandes. Deux `int` qui se divisent donnent un `int`, et un `int` ne sait pas stocker `3.5`. Le compilateur n'invente pas un type décimal pour vous : il fait une division entière et garde le quotient.

Pour obtenir `3.5`, il faut qu'au moins un des deux opérandes soit un nombre à virgule. Écrire `7.0 / 2.0` suffit, ou même `7.0 / 2` : dès qu'un `double` apparaît dans le calcul, l'autre nombre est converti et la division devient une vraie division décimale.

<CodePlayground language="c" starterCode={`\`\`\`c
#include <stdio.h>

int main(void) {
    int entier = 7 / 2;          /* division entiere : 3 */
    double reel = 7.0 / 2.0;     /* division reelle  : 3.5 */
    double mixte = 7.0 / 2;      /* un double suffit : 3.5 */

    printf("7 / 2     = %d\\n", entier);
    printf("7.0 / 2.0 = %.1f\\n", reel);
    printf("7.0 / 2   = %.1f\\n", mixte);

    return 0;
}
\`\`\``} />

<Callout type="warning">
Le piège le plus courant : on déclare `double moyenne = 5 / 2;` en croyant obtenir `2.5`. Erreur. Le `5 / 2` est calculé d'abord en division entière (résultat `2`), et c'est ce `2` qui est ensuite rangé dans le `double`. La conversion arrive trop tard. Il faut écrire `5.0 / 2` pour que le calcul lui-même soit décimal.
</Callout>

Le compagnon de la division entière, c'est le modulo, noté `%`. Il donne le reste de la division. `7 % 2` vaut `1`, parce que 7 contient trois fois 2 et qu'il reste 1. Ce n'est pas un gadget : tester si `n % 2` vaut `0` est la façon standard de savoir si un nombre est pair.

<CodePlayground language="c" starterCode={`\`\`\`c
#include <stdio.h>

int main(void) {
    printf("17 / 5 = %d\\n", 17 / 5);    /* quotient : 3 */
    printf("17 %% 5 = %d\\n", 17 % 5);    /* reste : 2 */

    int n = 8;
    printf("%d %% 2 = %d (0 donc pair)\\n", n, n % 2);

    return 0;
}
\`\`\``} />

## comparer et la logique

Pour décider quelque chose, il faut comparer. Les opérateurs de comparaison renvoient un résultat vrai ou faux : `<` plus petit, `>` plus grand, `<=` et `>=` avec le « ou égal », `==` égal, et `!=` différent.

Faites bien attention au double signe de `==`. Comparer deux valeurs, c'est `==`. Le simple `=` n'est pas une comparaison, c'est une affectation : il met une valeur dans une variable. Confondre les deux est l'une des erreurs les plus traîtresses du langage, parce qu'elle ne provoque souvent aucun message du compilateur.

Regardez ce que devient un `if` quand on se trompe :

<CodePlayground language="c" starterCode={`\`\`\`c
#include <stdio.h>

int main(void) {
    int age = 15;

    /* On voulait tester l'egalite, on a ecrit une affectation */
    if (age = 18) {
        printf("Le test est passe alors que age vaut %d !\\n", age);
    }

    /* La version correcte */
    if (age == 18) {
        printf("age vaut bien 18\\n");
    } else {
        printf("age ne vaut pas 18, il vaut %d\\n", age);
    }

    return 0;
}
\`\`\``} />

Dans le premier `if`, `age = 18` range 18 dans `age` puis renvoie `18`. Comme `18` est non nul, la condition est considérée comme vraie, et le bloc s'exécute même si l'intention était de tester `15`. Le programme ne plante pas, il fait juste silencieusement le mauvais choix.

On combine les comparaisons avec les opérateurs logiques. `&&` est le ET : vrai seulement si les deux côtés sont vrais. `||` est le OU : vrai dès qu'un des deux côtés est vrai. `!` est le NON : il inverse. Ces opérateurs sont paresseux. Dans `a && b`, si `a` est déjà faux, `b` n'est même pas évalué, puisque le résultat est joué d'avance.

<CodePlayground language="c" starterCode={`\`\`\`c
#include <stdio.h>

int main(void) {
    int age = 20;

    printf("age >= 18         : %d\\n", age >= 18);
    printf("age != 20         : %d\\n", age != 20);

    int adulte_plausible = (age >= 18) && (age < 130);
    printf("adulte plausible  : %d\\n", adulte_plausible);

    int hors_norme = (age < 0) || (age > 130);
    printf("hors norme        : %d\\n", hors_norme);

    return 0;
}
\`\`\``} />

## pas de vrai booléen

Vous avez peut-être remarqué que les comparaisons s'affichent comme des nombres : `1` ou `0`. Ce n'est pas un détail d'affichage. En C historique, il n'existe pas de type booléen séparé. La règle est purement numérique : `0` vaut faux, et toute autre valeur vaut vrai. Pas seulement `1`. Aussi bien `42` que `-1` ou `0.7` comptent comme vrais.

Une comparaison qui réussit produit `1`, une comparaison qui échoue produit `0`. Et un `if` ne demande pas un booléen, il demande juste un nombre : il exécute son bloc si ce nombre est différent de zéro.

C'est pour ça qu'on lit souvent `if (compteur)` sans aucun opérateur de comparaison. Ça signifie « si compteur est non nul ». Et `if (!reste)` signifie « si reste vaut zéro ». Une fois la règle intégrée, ces tournures deviennent naturelles, et elles éclairent au passage pourquoi `if (age = 18)` ne déclenche aucune erreur : pour le compilateur, c'est juste un nombre non nul.

## incrémentation

Ajouter ou retirer 1 à une variable arrive si souvent que C a des opérateurs dédiés : `++` augmente de 1, `--` diminue de 1. On les croise partout, surtout dans les boucles.

Il existe deux positions. Écrit avant la variable, `++i`, c'est la pré-incrémentation : on incrémente, puis on utilise la nouvelle valeur. Écrit après, `i++`, c'est la post-incrémentation : on utilise l'ancienne valeur, puis on incrémente. Dans la plupart des cas, par exemple à la fin d'une boucle, les deux donnent le même effet et le choix n'a pas d'importance. La nuance ne compte que lorsqu'on lit la valeur dans la même expression.

<CodePlayground language="c" starterCode={`\`\`\`c
#include <stdio.h>

int main(void) {
    int i = 5;
    printf("post : %d\\n", i++);   /* affiche 5, puis i passe a 6 */
    printf("i vaut maintenant %d\\n", i);

    int j = 5;
    printf("pre  : %d\\n", ++j);   /* j passe a 6, puis affiche 6 */
    printf("j vaut maintenant %d\\n", j);

    return 0;
}
\`\`\``} />

Tant que vous débutez, gardez ces opérateurs sur leur propre ligne, comme `i++;`. La distinction pré/post deviendra utile plus tard, quand vous lirez du code plus dense.

## à retenir

- Les opérateurs `+ - * /` calculent comme en maths, avec les priorités usuelles et les parenthèses pour forcer l'ordre.
- Entre deux `int`, `/` est une division entière : `7 / 2` vaut `3`, la partie décimale est coupée. Il faut au moins un opérande à virgule (`7.0 / 2`) pour un résultat décimal, et la conversion doit avoir lieu pendant le calcul, pas après.
- `%` donne le reste de la division entière ; `n % 2 == 0` teste si `n` est pair.
- Les comparaisons sont `< > <= >= == !=`. Le `==` teste l'égalité ; le `=` seul affecte, et le confondre dans un `if` est un bug silencieux.
- `&&` `||` `!` combinent des conditions et s'évaluent de gauche à droite, sans aller plus loin que nécessaire.
- Il n'y a pas de booléen séparé : `0` est faux, tout le reste est vrai ; une comparaison réussie renvoie `1`.
- `++` et `--` ajoutent ou retirent 1 ; la nuance entre `i++` et `++i` ne compte que si on lit la valeur dans la même expression.
